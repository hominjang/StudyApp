# 공통 설계 진행 계획

학습의 목적과 흐름을 정하고, 플랫폼에서 함께 사용할 데이터와 학습 규칙을 구체화한다. 각 플랫폼의 코드와 저장소 연결은 해당 구현 계획에서 관리한다.

## 공통 산출물과 상태

| 순서 | 작업 | 산출물 | 상태 |
| --- | --- | --- | --- |
| 1 | 목적·범위·설계 원칙과 공통 책임 정의 | [전체 설계](../전체설계/README.md) | 초기 설계 정리 완료 |
| 2 | 출제·채점·기록·재출제 규칙 정의 | [학습 규칙](../상세설계/학습규칙/README.md) | 초기 설계 정리 완료 |
| 3 | 자료·기록 구조와 식별·변환·검증 정의 | [데이터](../상세설계/데이터/README.md) | 초기 설계 정리 완료 |
| 4 | 실제 자료의 코드 분리와 Git 제외 원칙 정의 | [데이터와 Git 관리](../개발원칙/01_실제데이터와Git관리.md) | 원칙·ignore 적용 |
| 5 | 공통 기준을 각 플랫폼 구현에 연결 | [Android](../../Android/README.md), [Window](../../Window/README.md) | Windows 시험·채점·기록 조회·자동 저장과 재개·오답 재학습까지 구현, Android 작성 전 |

## 자료 준비와 검토 이력

로컬 초기 자료는 Android 주제 107문항과 일반 CS 147문항이며 문항 ID·정답을 보존했다. 구조·원문 대응과 채점 예시 1,705건을 확인한 이력이 있다. 원문의 부분 변환·보류 항목과 기존 22문항 파일럿은 추가 자료 준비의 검토 이력이다. 실제 자료와 관련 파일은 Git에서 제외한다.

Windows 저장 설계와 17개 독립 모델 시나리오의 검토는 [Window 설계 검토](../../Window/작업계획/02_설계검토.md), 실제 코드 연결의 설계는 [Window 구현 설계 검토](../../Window/작업계획/05_구현설계검토.md)에 둔다. 설계 검증과 앱 구현 완료를 구분한다.

## 진행 방식

전체 설계는 방향과 원칙을 간결하게 유지하고, 세부 내용은 주제별 파일에 작성한다. 각 폴더 README는 경로를 안내한다. 공통 요구의 변경은 공통 문서에서, 기술·화면·파일 위치 등 플랫폼 결정은 각 플랫폼 문서에서 갱신한다.

다음 Windows 구현 작업은 [구현 진행 계획](../../Window/작업계획/04_구현진행계획.md), Android의 준비 상태는 [Android 작업 계획](../../Android/작업계획/README.md)에서 확인한다.
