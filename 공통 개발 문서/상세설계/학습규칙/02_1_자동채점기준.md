# 자동 채점 판정 기준

상태: 초기 설계 기준. 사용자 요구와 이번 작업의 구현 기준을 함께 반영했다.

이 문서는 단답형 자동 채점에 적용한다. 단답이나 3~4개 단어로 된 짧은 문장을 정답으로 작성하고, 대표 정답이나 등록된 허용 표기와 정확히 일치해야 자동 정답이다. 서술형에 이 비교를 적용하지 않는다. 채점 흐름은 [채점](02_채점.md), 확장할 사용자 평가는 [사용자 평가와 정정](02_2_사용자평가와정정.md)을 따른다.

## 판정 기준

- 대표 정답이나 등록된 허용 표기 중 하나와 완전히 같으면 정답, 어느 것과도 같지 않으면 오답으로 판정한다.
- 공백과 대소문자 및 문장부호를 그대로 비교하며, 앞뒤 공백도 제거하지 않는다.
- 미응답은 제출 전 안내하고, 그대로 최종 제출하면 오답으로 판정한다.
- 설명형 모범 답변의 의미를 평가하거나 필수 키워드를 임의로 추출하지 않는다.

동의어나 약어 등 다른 표기는 허용 표기로 등록된 경우에만 인정한다. 유사 표현을 자동으로 추가하지 않는다.

## 비교 처리

- 정답 문자열이 없거나 형식이 잘못되었으면 오류를 안내하고, 해결 후 출제한다.
- 허용 표기를 생략했거나 빈 배열이면 대표 정답 하나만 비교 대상으로 삼는다.
- 입력 답변을 자동으로 고치거나 정리하지 않고 비교하고 보존한다.

## 미응답 처리

미응답 문항을 안내할 때 답변을 작성하러 돌아갈 수 있게 한다. 그대로 제출하면 미응답 문항을 오답으로 기록한다. 채점 처리 실패에 따른 미채점과는 구분한다.

빈 문자열과 아래 공백 문자로만 이루어진 답변은 모두 미응답으로 보고 오답 사유를 함께 보존한다. 공백 문자가 아닌 문자가 하나라도 있으면 응답으로 보고 일반 비교를 적용한다. 미응답 여부를 확인할 때도 저장할 원문을 trim하거나 대소문자를 바꾸지 않는다. 비교 규칙의 식별값은 `exact-v1`이다.

### 미응답 판정의 공백 문자

Unicode `White_Space` 속성의 25자를 공백 문자로 본다. 플랫폼 기본 함수(`str.isspace`, `char.IsWhiteSpace`, Kotlin `isWhitespace`, Rust `char::is_whitespace` 등)는 범위가 서로 다를 수 있으므로, 모든 플랫폼이 이 목록을 직접 사용해 판정한다.

| 코드 포인트 | 문자 |
| --- | --- |
| U+0009~U+000D | 탭, 줄바꿈, 세로 탭, 폼 피드, 캐리지 리턴 |
| U+0020 | 공백 |
| U+0085 | 다음 줄(NEL) |
| U+00A0 | 줄바꿈 없는 공백(NBSP) |
| U+1680 | 오검 공백 |
| U+2000~U+200A | 폭이 다른 공백 11자 |
| U+2028, U+2029 | 줄 구분자, 문단 구분자 |
| U+202F | 좁은 줄바꿈 없는 공백 |
| U+205F | 수학용 중간 공백 |
| U+3000 | 전각 공백 |

U+001C~U+001F(정보 구분 문자), U+200B(폭 없는 공백), U+FEFF(BOM)는 공백 문자가 아니다. 이 문자가 들어 있는 답은 응답으로 보고 일반 비교를 적용한다.

## 문항 형식 연결

질문과 짧은 정답의 구조는 [학습 데이터](../데이터/01_학습데이터.md), 작성 기준은 [문항 작성](../데이터/04_단답형문항작성.md)에서 정의한다. 설명형 원문의 재작성은 [자료 변환 절차](../데이터/04_1_자료변환절차.md)를 따른다.

## 판정 예시

대표 정답이 `서울`이고 허용 표기에 `서울특별시`를 등록했다면 두 표기를 각각 정답으로 인정한다. ` 서울 `과 등록하지 않은 `서울입니다`는 오답이다.

정답 표기가 `A B C`인 짧은 문장이면 `A  B C`처럼 공백이 하나 더 있어도, 그 표기를 따로 등록하지 않았다면 오답이다.

전각 공백(U+3000)이나 탭만 입력한 답은 미응답(`unanswered`)이다. 폭 없는 공백(U+200B)만 입력한 답은 응답으로 보며, 정답 표기와 다르므로 `no_match` 오답이다.
