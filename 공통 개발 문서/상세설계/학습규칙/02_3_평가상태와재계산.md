# 평가 상태·순서·재계산 계약 초안

작성일: 2026-11-26. 상태: 미확정 정책 초안·DB 2 평가/복습 서비스 검증 구현. 실제 사용자 DB 전환/배포 전 정책 검토는 남아 있다. 아래 권장안은 사용자 확정으로 기록하지 않는다. 기존 앱의 단답형 정책은 그대로 유지한다.

## 남은 정책의 권장 조합

| 항목 | 권장안 | 영향 |
| --- | --- | --- |
| 부분정답 | 오답 대상 편입/유지·연속 정답 0 | 일부 인정과 복습 필요를 함께 표현 |
| 미평가 | 집계 제외·연속 횟수 유지 | 나중에 평가하면 원래 순서에서 다시 계산 |
| 미응답 | 기존 25자 기준으로 오답·평가 정정 불가 | 빈 원문을 정답으로 바꾸지 않음 |
| 단답형 정정 | 해당 응답의 정답/부분정답/오답 변경 허용 | 최초 자동 판정 보존, 자료 허용 표기와 분리 |
| 사용자 평가 | 최초 평가 뒤에는 세 판정 간 정정 허용, 미평가로 되돌리기는 초기 범위에서 제외 | 평가 취소 명령과 별도 집계 규칙을 늘리지 않음 |
| 완료 시점 | 제출 답변을 잠근 뒤 자동 처리 성공 시 시험 완료·완료 순번 부여 | 서술형 평가를 기다리지 않고 단답형 결과 반영 |
| 수동 복습 편입 | 편입 이후 3회 연속 정답으로 해제, 재편입은 새 주기 | 이전 정답 횟수를 가져와 즉시 해제하지 않음 |
| 손상된 집계 원천 | 영향 문항의 새 완료/평가/편입 쓰기를 차단하고 원문 보존 | 정상 문항 조회·별도 시험은 유지, 조용히 손상 행을 생략하지 않음 |

확정된 개수 표시는 이 표의 제안과 별개다. 시험 전체는 정답·부분정답·오답·미평가 합계가 문항 수와 같아야 한다. 미응답은 오답의 하위 사유이며 다섯 번째 평가가 아니다.

## 시험 상태와 평가 진행 상태

시험 상태는 기존 `in_progress → submitted → completed`를 유지하는 안이다. `submitted`는 원문 잠금 후 시스템 처리 대기/재시도, `completed`는 자동 처리·이력·집계가 저장된 상태다. 사용자의 미평가가 남아 있어도 시스템 처리가 성공하면 완료 상태가 된다.

평가 진행 상태는 완료 시험의 현재 유효 평가로 계산한다. 미평가가 하나라도 있으면 `pending`, 없으면 `complete`다. 진행 중·제출 처리 중에는 `not_available`로 반환하고 개수도 공개하지 않는다. 시스템 실패를 미평가로 바꾸지 않는다. 나중 평가를 기다리는 동안 새 시험을 시작할 수 있다.

완료 순번은 자동 처리 트랜잭션이 성공할 때 사용자별로 한 번만 부여한다. 초기 제출 잠금만 성공하고 자동 처리가 실패하면 아직 순번과 학습 반영은 없다. 나중 사용자 평가·정정으로 완료 순번과 최초 완료 시각을 바꾸지 않는다. 기록 목록은 기존 완료 순서를 유지하고 평가 변경 시각은 별도로 보여 준다.

## 재계산의 원천과 순서

실제 시험 시도와 수동 복습 편입을 한 사용자 안에서 순서가 정해진 이벤트로 보존한다. 시험의 이벤트 순서는 완료 처리 때 한 번 부여하고, 평가가 늦어져도 이동시키지 않는다. 수동 편입은 저장 성공 때 자신의 순서를 받으며 같은 시험 응시로 세지 않는다.

1. 대상 사용자의 묶음·문항 키별로 원천 이벤트를 순서대로 읽는다. 실제 응시 이벤트는 그 응답의 최신 유효 평가 하나를 사용한다.
2. 복습 대상이 아닐 때 정답은 대상 편입을 만들지 않는다. 오답·부분정답이면 대상·연속 0으로 만든다. 미평가는 상태를 바꾸지 않는다.
3. 복습 대상일 때 정답은 연속 횟수를 1 올리고 3이면 해제한다. 오답·부분정답은 연속 0, 미평가는 유지한다.
4. 수동 편입 이벤트는 대상·연속 0으로 만든다. 이미 대상인 문항에 반복 추가하면 새 이벤트를 만들지 않아 횟수가 초기화되지 않는다.
5. 과거 평가 정정은 같은 위치의 평가만 교체하고 이후 전체 순서를 다시 반영한다. 이미 저장된 수동 편입 이벤트는 평가 정정으로 삭제하지 않는다.

수동 편입 시점 이전에 생성했지만 아직 완료하지 않은 시험은 실제 완료 처리 순서를 따른다. 수동 추가로 가짜 답변·오답 판정·최초 오답 횟수를 만들지 않는다. 수동 삭제 기능은 초기 범위에서 제외하는 권장안이며, 해제 뒤 다시 추가하면 새로운 편입 이벤트를 만든다.

## 검증할 경계

| 원천 흐름 | 권장안의 기대 결과 |
| --- | --- |
| 오답 → 정답 → 미평가 → 정답 | 대상·연속 2, 미평가는 중립 |
| 위 미평가를 나중에 오답으로 평가 | 원래 위치에서 다시 계산해 대상·연속 1 |
| 수동 추가 → 정답 → 정답 → 정답 | 가짜 응시 없이 해제 |
| 수동 추가 → 정답 → 중복 추가 → 정답 | 추가는 멱등, 대상·연속 2 |
| 수동 추가 → 정답 → 부분정답 → 정답 | 대상·연속 1 |
| 과거 오답 정정, 그 뒤 수동 추가 존재 | 기존 수동 추가 이벤트 보존·그 위치부터 연속 계산 |

## 손상과 원자성

평가와 수동 복습 저장은 관련 모든 문항의 원천을 먼저 검사한다. 손상된 판정·순번이 있으면 해당 문항을 포함한 쓰기 요청 전체를 롤백하고 `ProgressSourceCorrupt`를 반환하는 안이다. 혼합 시험 일부만 완료하지 않는다. 목록에서 손상 행을 격리해도 원천을 조용히 빼고 집계하지 않는다. 손상 범위를 식별할 수 없으면 안전한 사용자 범위를 확인할 때까지 관련 쓰기를 차단하고 정상 조회와 원본 보존을 우선한다.

이력 추가·현재 평가·시험 개수·학습 상태와 요청 결과는 한 트랜잭션으로 저장한다. 버전 충돌이면 저장하지 않고 재조회를 안내한다. 응답 손실 재시도는 저장된 요청 결과를 반환하며 이벤트를 추가하지 않는다. [평가 이력](../데이터/02_4_평가이력.md), [Windows 명령 초안](../../../Window/구현설계/확장/02_명령과화면연결.md)
