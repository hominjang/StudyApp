# 원문 대응과 자료 변환 결과

상태: 초기 설계 기준. 사용자 요구와 이번 작업의 구현 기준을 함께 반영했다.

결과 문항에서 원문을 찾고, 원문 항목마다 무엇이 변환되거나 남았는지 확인할 수 있게 한다.

## 결과 문항의 원문 대응

보충 정보의 문항 항목에 선택 필드 `source_refs`를 추가하는 안을 사용한다. 변환으로 만든 문항에는 이 필드를 채운다.

| 필드 | 형식 | 역할 |
| --- | --- | --- |
| `source_refs` | 객체 배열 | 해당 문항을 만든 원문 항목들의 목록 |
| `source_refs[].dataset_id` | 문자열 | 원문 묶음 식별자 |
| `source_refs[].item_id` | 문자열 | 원문 항목 식별자 |

결과 문항과의 연결은 보충 정보 자체의 `dataset_id`와 `items[].id`로 구분한다. 원문 ID를 결과 문항 ID로 덮어쓰지 않는다. 원문 하나가 여러 결과 문항의 출처가 될 수 있다.

`sources`는 참고 URL을, `source_refs`는 보관한 원문 데이터의 항목을 가리킨다. 원문 내용은 기존 참고 자료로 보존한다.

## 원문 항목별 변환 보고서

| 필드 | 내용 |
| --- | --- |
| `source_dataset_id` | 원문 묶음 식별자 |
| `source_item_id` | 원문 항목 식별자 |
| `target_refs` | 시험용 결과의 묶음·문항 식별자 목록 |
| `status` | `converted`, `partial`, `held`, `excluded` 중 하나 |
| `reason` | 부분 변환·보류·제외 시 남길 사유 |

`converted`는 선택한 학습 내용을 변환 완료한 상태다. `partial`은 일부 문항을 만들었지만 남은 내용이 있는 상태이며 남은 부분을 사유에 적는다. `held`는 보류, `excluded`는 중복 등 명시한 이유로 변환 대상에서 제외한 상태다.

보고서는 모든 입력 항목을 포함한다. `converted`와 `partial`은 하나 이상의 시험용 결과를 참조한다. 시험용 결과가 없는 항목도 빈 `target_refs`와 상태 및 사유를 남겨 누락과 의도적인 보류를 구분한다. 초안 문항은 시험용 결과 참조에 포함하지 않는다.

## 산출물의 역할

학습 데이터와 보충 정보는 앱에서 사용한다. 변환 보고서는 자료 준비 과정의 추적과 재작업에 사용하며 학습 기록과 분리한다. 실제 파일명과 보고서 직렬화 형식은 변환 도구 구현에서 정한다.
