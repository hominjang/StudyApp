# 설명형 자료의 시험 문항 변환 절차

상태: 초기 설계 기준. 사용자 요구와 이번 작업의 구현 기준을 함께 반영했다.

설명형 참고 자료를 짧은 정답의 시험용 자료로 만든다. 변환은 자료 준비 단계에서 수행하고, 시험에서는 준비된 문항을 읽어 출제한다.

## 입력과 출력

입력은 원문 묶음과 항목 식별자가 있는 질문·답변 및 보충 정보다. 입력 형식이 다르면 먼저 이 구조로 정리한다. 기존 참고 자료는 원문으로 보관한다.

| 출력 | 내용 |
| --- | --- |
| 시험용 학습 데이터 | 새 문항 ID, 질문, 대표 정답, 선택적 허용 표기 |
| 보충 정보 | 해설과 예시 및 출처, 원문 대응 정보 |
| 변환 보고서 | 원문 항목별 결과 문항과 보류 및 제외 사유 |

## 변환 순서

1. **입력 확인:** 원문 식별자와 질문 및 답변을 확인하고 변환 대상을 목록으로 만든다.
2. **개념 분리:** 원문에서 학습할 개념과 관계를 나눈다. 근거가 불명확한 내용은 보류한다.
3. **문항 생성:** 개념별로 질문을 재작성하고 대표 정답과 필요한 허용 표기를 지정한다.
4. **자료 분리:** 긴 설명과 예시를 보충 정보로 옮기고 결과 문항을 원문에 연결한다.
5. **형식 검증:** 구조와 ID 및 원문 연결, 정답의 길이와 표기를 검사한다.
6. **내용 검토:** 원문의 의미, 질문의 명확성, 정답의 정확성과 허용 표기의 타당성을 확인한다.
7. **결과 정리:** 검증과 검토를 통과한 문항으로 시험용 묶음을 만들고 변환 보고서를 함께 남긴다.

형식 검사는 규칙으로 자동화할 수 있다. 개념 분리와 질문 작성 및 의미 검토는 별도 작업으로 다루며, 구체적인 생성 도구는 구현 단계에서 선택한다.

## 재실행과 보류

변환하기 어려운 항목은 이유를 남기고 원문을 보존한다. 검토 전 초안은 작업 자료로 관리하고, 시험용 묶음에는 통과한 문항만 넣는다.

같은 변환 작업을 다시 수행할 때는 기존 원문 대응을 확인한다. 같은 결과 문항의 문구를 교정하면 ID를 유지하고, 새 학습 대상으로 바뀌거나 문항이 분리되면 새 ID를 부여한다. 재실행 때마다 동일 문항을 새 ID로 중복 생성하지 않는다.

세부 산출물과 처리 상태는 [원문 대응과 변환 결과](04_2_원문대응과변환결과.md), 통과 기준은 [문항 검증과 검토](04_3_문항검증과검토.md)에서 정의한다.
