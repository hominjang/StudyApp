# 문항 유형과 선행 개념

작성일: 2026-11-26. 상태: 확장 설계 방향. 아래 논리 구성은 새 JSON 필드나 앱 지원이 확정된 명세가 아니다. [확장 계획](../../작업계획/05_학습방식확장계획.md)

유형별 필드와 선택 연결 위치의 후보는 [확장 자료 교환 형식](06_확장자료교환형식.md)에 구체화했다. 아래 방향과 구분해 검토하며 아직 파서에 적용하지 않았다.

서술형 참고 답안에 단답형의 4단어 상한을 적용하지 않는 것은 2026-11-26 사용자 확정 사항이다. 새 형식의 필드·입력/저장용 크기 제한은 확장 2에서 구체화하며 단답형 검증을 그대로 재사용하지 않는다. 기존 DB 1은 단답형을 유지하고 신규 DB 2는 서술형/혼합 시험과 사용자 평가를 지원한다. 실제 자료 보강·배포는 남아 있다.

## 문항 유형

| 유형 | 묻는 내용 | 문항의 평가 기준 | 입력과 평가 |
| --- | --- | --- | --- |
| 단답형 | 용어 이름·짧은 명칭·핵심 사실 | 대표 정답과 선택적 허용 표기. 각각 4단어 이하 | 한 줄 입력·기존 완전 일치 자동 채점 |
| 서술형 | 용어의 정의·이유·차이·종류·사례 설명 | 참고 답안과 확인할 핵심 내용. 4단어 상한을 적용하지 않음 | 여러 줄 입력·제출 후 사용자 평가 |

정의 문항을 모두 단답형으로 만들지는 않는다. 정의를 보고 용어를 떠올리게 하려면 단답형, 용어의 의미를 자기 말로 설명하게 하려면 서술형으로 만든다. 여러 종류를 나열하는 문제는 답의 순서·표현을 문자열 하나와 강제로 일치시키지 않도록 유형을 선택한다.

서술형의 참고 답안과 핵심 내용은 평가에 필요한 문항 본체의 정보다. 선택적인 보충 해설만으로 대신하지 않으며, 핵심 내용은 자동 키워드 일치 채점용이 아니다. 단답형의 긴 해설·예시는 기존대로 보충 정보에 둔다.

## 기초 문항 작성과 연결

1. 질문과 서술형 참고 답안·핵심 내용에 등장하는 용어·약어·개념 중 먼저 알아야 할 것을 점검한다.
2. 필요한 용어의 정의를 묻는 기초 문항을 별도로 만든다. 그 질문에도 생소한 용어가 연쇄적으로 들어가지 않는지 확인한다.
3. 기초 문항 뒤에 특징·조건을 묻는 이해 문항, 상황에 적용하는 문항을 구성한다. 모든 개념에 세 단계를 의무적으로 만들지는 않는다.
4. 약어는 분야와 의미를 좁힐 수 있도록 질문에 맥락을 넣는다.
5. 내용 검토에서 정의의 정확성과 학습 순서·중복·질문의 모호함을 확인한다. 참고 답안·핵심 내용도 생소한 용어만으로 설명되어 있지 않은지 검토한다.

문항별 선행 기초 문항 연결은 묶음 ID와 문항 ID의 조합을 기준으로 설계한다. 같은 기초 문항을 여러 문항에서 참조해 불필요한 복제를 줄인다. 연결이 없더라도 각 문항은 독립적으로 읽고 풀 수 있어야 한다. 연결은 추천 학습을 위한 정보이며 기존 무작위·순서대로 출제 설정을 자동으로 바꾸거나 추가 문항을 몰래 출제하지 않는다.

기초 문항도 다른 문항과 같은 자료 구조로 둔다. 사용자는 결과·회고에서 모르는 기초 부분에 연결된 문항을 오답노트에 추가하고, 이후 기존 오답 우선·오답만 출제로 복습한다. 별도 기초 학습 모드·전용 시험 생성·선수학습 잠금을 추가하지 않는 방향으로 2026-11-26 사용자 요구를 반영했다. 상위 문항의 답변과 판정은 그대로 두며 구체적인 편입 저장 방식은 별도 설계한다.

수동 편입 대상은 묶음 ID와 문항 ID로 식별되는 기초 문항이다. 해당 기초 문항이 아직 없으면 자료 준비에서 보강할 대상으로 남기고, 모르는 용어의 이름만으로 질문·정답을 임의 생성하지 않는다. 연결된 문항을 찾지 못하면 편입할 수 없음을 안내한다. [수동 오답노트 기준](../학습규칙/04_1_오답대상관리.md#수동-오답노트-편입-확장)

자기 참조·순환 참조·없는 문항 참조의 검사와 다른 묶음이 설치되지 않은 경우의 안내를 새 교환 형식에서 정의한다. 용어를 알아야 한다는 이유로 질문에 해당 문항의 정답을 함께 노출하지 않는다.

## 새 형식에서 구체화할 정보

| 정보 | 역할 |
| --- | --- |
| 문항 유형 | 단답형과 서술형의 입력·검증·평가 분기 |
| 유형별 평가 기준 | 대표 정답/허용 표기 또는 참고 답안/핵심 내용 |
| 학습 단계와 선행 연결 | 기초·이해·응용 안내와 관련 문항 탐색. 필수 여부는 명세에서 결정 |

정확한 필드명과 2.0 교환 버전은 확장 자료 교환 형식에 정의했다. 기존 JSON 1.0은 단답형으로 유지하고, 기존 파일에 새 유형을 무시한 채 섞어 넣지 않는다. 새 형식은 지원하는 앱에서만 읽게 하며, 알 수 없는 유형을 단답형으로 간주해 채점하지 않는다.

새 문항 유형은 반드시 기존 1.0과 다른 schema_version의 형식으로만 표현한다. 기존 DB 1 등록 경로의 1.0 파서는 알 수 없는 유형 필드의 혼입을 자동으로 막아주지 않으므로 파일 작성 단계에서도 1.0에 새 유형을 넣지 않는다. 신규 DB 2 파서는 새 유형 전용 필드 혼입을 거부하고 선행 연결을 보충 파일에서 읽는다. 세부 기준은 확장 자료 형식에 정의했다.

출제 시 문항 유형과 해당 평가 기준을 함께 보존한다. 원본을 고쳐 과거 시험의 유형이나 기준을 바꾸지 않는다. 기존 문항의 학습 대상이 달라지거나 단답형에서 서술형으로 바꾸면 새 문항 ID를 부여한다. [평가 이력](02_4_평가이력.md), [자료 변환](04_1_자료변환절차.md)
