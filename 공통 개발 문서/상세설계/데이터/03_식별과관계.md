# 데이터 식별자와 연결 관계

상태: 초기 설계 기준. 사용자 요구와 이번 작업의 구현 기준을 함께 반영했다.

이름이나 문장이 바뀌어도 같은 대상을 식별할 수 있도록 저장된 ID로 연결한다. 제목과 질문 문장 및 배열 위치는 원본 문항을 식별하는 키로 사용하지 않는다.

## 식별 범위 기준

| 대상 | 식별 키 | 범위 |
| --- | --- | --- |
| 데이터 묶음 | `dataset_id` | 관리하는 학습 자료 안에서 유일 |
| 문항 | `dataset_id` + `item_id` | 묶음 안에서 문항 ID가 유일 |
| 보충 정보 | `dataset_id` + `item_id` | 해당 문항에 연결 |
| 사용자 | `learner_id` | 사용자 기록 영역을 구분 |
| 시험 | `exam_id` | 보관하는 시험 기록 안에서 유일 |
| 문항별 응답 | `exam_id` + `position` | 한 시험의 문항 위치별로 유일 |
| 문항 학습 상태 | `learner_id` + `dataset_id` + `item_id` | 사용자별 문항 상태가 하나 |

학습 데이터의 `items[].id`와 보충 정보의 `items[].id`가 기록에서 참조하는 `item_id`다. 서로 다른 묶음에서 같은 문항 ID를 써도 별개 문항으로 구분한다.

## 연결 기준 기준

- 시험의 `learner_id`는 기록 소유자를 가리킨다. 사용자 식별자는 기록 영역을 처음 만들 때 생성하고 이후 실행에서도 유지한다.
- 문항별 응답은 소속 시험과 출제 당시 원본 문항을 참조한다. 같은 시험에서 동일 묶음과 문항 조합은 한 번만 출제한다.
- 문항 학습 상태는 같은 사용자의 완료된 시험 중 동일 묶음과 문항을 가리키는 결과에서 계산한다.
- `schema_version`은 데이터 형식 버전이며 자료나 문항의 식별자로 사용하지 않는다.

## ID 형식

| 대상 | 형식 | 만드는 주체 |
| --- | --- | --- |
| `dataset_id`, `item_id` | 소문자 영문·숫자·하이픈. 정규식 `^[a-z0-9]+(-[a-z0-9]+)*$`, 1~64자 | 자료 작성자. 앱은 가져온 값을 그대로 보존 |
| `exam_id`, `learner_id` | 소문자 하이픈 형식의 UUID v4. 예: `3f2a9c1e-5b7d-4e8a-9c21-7d4e5f6a8b90` | 앱 |
| 독립 복제한 자료의 `dataset_id` | 위와 같은 UUID v4. 자료 ID 정규식도 만족 | 앱 |

형식에 맞지 않는 `dataset_id`나 `item_id`가 있는 자료는 가져오기에서 오류로 거부한다. 소문자 변환 등으로 ID를 자동으로 고치지 않는다. 보충 정보의 `source_refs`는 원문 식별자를 그대로 보존하며 이 형식 검사의 대상이 아니다.

ID는 빈 값 없이 저장하고 대소문자와 공백을 임의로 바꾸지 않는다. 앱이 만든 UUID가 같은 범위의 기존 ID와 겹치면 새로 생성한다.

내용 수정과 재가져오기는 [변경과 재가져오기](03_1_변경과재가져오기.md), 원본과 기록의 연결 검증은 [기록 연결과 보존](03_2_기록연결과보존.md)을 따른다.
