# 학습 자료 변경과 재가져오기

상태: 초기 설계 기준. 사용자 요구와 이번 작업의 구현 기준을 함께 반영했다.

같은 학습 대상을 수정할 때는 기존 식별자를 유지하고, 별개의 학습 대상으로 바뀌면 새 식별자를 부여한다. 설명형 원문의 재작성은 [자료 변환 절차](04_1_자료변환절차.md)를 따른다.

## 변경별 식별자 기준

| 변경 | 처리 |
| --- | --- |
| 파일명과 자료 제목 또는 문항 순서 변경 | 묶음과 문항 ID 유지 |
| 질문의 오탈자나 의미를 유지하는 표현 수정 | 문항 ID 유지 |
| 같은 학습 대상의 정답 오탈자 교정과 허용 표기 추가 | 문항 ID 유지. 진행 중 시험과 과거 판정은 변경하지 않음 |
| 묻는 개념이나 정답의 의미가 다른 문항으로 변경 | 새 문항 ID 부여 |
| 설명형 질문을 여러 짧은 정답 문항으로 분리 | 각 문항에 새 ID 부여하고 원문과 대응 보존 |
| 기존 자료를 독립된 자료로 복제 | 새 묶음 ID 부여 |

제거한 문항의 ID는 다른 문항에 재사용하지 않는다. 다른 묶음으로 옮긴 문항은 연결 키가 바뀌므로 별개의 학습 대상으로 취급한다.

## 재가져오기 기준

1. 같은 `dataset_id`가 있는지 확인한다.
2. 동일 ID와 동일 내용이면 같은 자료로 처리하고 문항이나 학습 기록을 중복 생성하지 않는다.
3. 동일 ID인데 내용이 다르면 변경 내역을 확인한 뒤 해당 자료의 갱신으로 적용한다. 다른 자료로 추가하려면 새 묶음 ID를 부여한다.
4. 갱신된 원본은 이후 새로 만드는 시험에 적용한다. 이미 시작한 시험과 완료 기록은 보존한다.

질문 문장이 같다는 이유만으로 다른 ID의 문항을 합치거나 학습 기록을 옮기지 않는다. 갱신 시 문항의 추가와 제거를 적용하는 구체적인 절차는 가져오기와 내보내기 설계에서 정의한다.

## 기존 기록과의 관계

같은 ID의 자료를 갱신해도 과거 판정과 연속 정답 횟수를 새 정답으로 소급 재채점하지 않는다. 학습 상태는 보존된 완료 판정에서 계산한다.

앱의 자료 갱신에서 빠진 문항은 비활성화하고 시험과 응답 기록은 남긴다. 같은 ID로 다시 가져오면 기존 기록과 연결한다. 외부 JSON 원본 파일의 삭제만으로 DB 자료가 제거되지는 않는다. 연결 키는 [식별과 관계](03_식별과관계.md), 갱신 적용은 [학습 데이터 저장](../../../Window/저장방식/01_학습데이터저장.md)을 따른다.
