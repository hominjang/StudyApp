# 변환 문항의 검증과 내용 검토

상태: 초기 설계 기준. 사용자 요구와 이번 작업의 구현 기준을 함께 반영했다.

형식이 맞는지 검사하는 작업과 학습 내용이 맞는지 검토하는 작업을 구분한다. 자료 변환의 처리 순서는 [자료 변환 절차](04_1_자료변환절차.md)를 따른다.

## 형식 검사

- 묶음과 문항의 필수 필드, 자료형, 빈 값, 중복 ID를 확인한다.
- 대표 정답과 허용 표기의 길이, 앞뒤 공백, 줄바꿈을 검사한다. 원문이나 입력 값을 자동으로 잘라 고치지 않는다.
- 허용 표기는 생략하거나 빈 배열로 둘 수 있다. 지정했다면 각 원소가 비어 있지 않은 문자열인지 확인한다. 대표 정답이나 다른 허용 표기와 같은 값이 반복되면 정리 대상으로 안내한다.
- 대표 정답과 허용 표기가 4단어를 넘으면 형식 오류다. 4단어 이하라는 사실만으로 짧은 정답이라고 보지 않고, 긴 설명을 잘못 통과시키지 않도록 내용 검토로 연결한다. 단어 수 기준은 [문항 작성](04_단답형문항작성.md)을 따른다.
- 결과 문항과 보충 정보가 같은 식별자로 연결되고, `source_refs`가 실제 보관한 원문 항목을 가리키는지 확인한다.
- 모든 원문 항목이 변환 보고서에 있는지, 결과 참조가 실제 시험용 문항을 가리키는지 확인한다. 부분 변환·보류·제외에는 사유가 있어야 한다.

## 내용 검토

- 질문이 하나의 학습 대상을 명확하게 묻고 짧은 답을 요구하는지 확인한다.
- 필요한 조건과 표기 형식이 질문에 있어 정답을 하나로 좁힐 수 있는지 확인한다.
- 대표 정답과 허용 표기가 원문 및 참고 근거와 일치하는지 확인한다. 원문에 오류나 모호함이 있으면 근거를 확인하거나 보류한다.
- 문항을 나누는 과정에서 원문의 조건이나 의미가 바뀌지 않았는지 확인한다.
- 허용 표기끼리 같은 답을 뜻하는지, 질문에 대표 정답이나 등록된 허용 표기가 그대로 노출되지 않았는지 확인한다.
- 같은 문장을 그대로 복제한 문항과 비슷한 문항을 검토한다. 질문이 같다는 이유만으로 자동 병합하지 않는다.

## 완전 일치 판정 점검

대표 정답과 등록한 허용 표기는 각각 정답으로 판정되어야 한다. 등록하지 않은 공백·대소문자·문장부호 차이는 오답으로 판정되어야 한다. 미응답은 안내 후 제출하면 오답이다.

판정 기대값은 [자동 채점 기준](../학습규칙/02_1_자동채점기준.md)을 따르며, 실제 채점 도구가 준비되면 같은 예시로 구현을 검증한다.

## 시험용 자료 포함 기준

형식 검사에서 오류가 없고 내용 검토를 마친 문항만 시험용 묶음에 포함한다. 문제를 고친 경우 관련 검사를 다시 수행하고, 포함한 문항과 보류한 항목을 [변환 보고서](04_2_원문대응과변환결과.md)에 반영한다.

형식 검사를 통과했다는 사실만으로 의미 검토가 완료되었다고 표시하지 않는다. 보류와 제외를 포함한 원문 전체의 처리 결과를 확인한 뒤 자료 준비 상태를 정리한다.
