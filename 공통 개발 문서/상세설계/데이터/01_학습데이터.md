# 질문과 정답 학습 데이터

상태: 초기 설계 기준. 사용자 요구와 이번 작업의 구현 기준을 함께 반영했다.

학습 자료는 데이터 묶음과 문항으로 구성한다. 문항에는 질문과 대표 정답 하나를 두고, 필요하면 허용 표기를 추가한다. 학습 기록과 보충 정보는 별도로 연결한다.

## 데이터 묶음 기준

| 필드 | 형식 | 역할 |
| --- | --- | --- |
| `schema_version` | 문자열 | 초기 교환 형식은 `1.0`. DB 구조 버전과 별도 |
| `dataset_id` | 문자열 | 묶음 식별자 |
| `title` | 문자열 | 자료 이름 |
| `items` | 문항 배열 | 자료에 포함된 문항과 기본 순서 |

이 구조는 파일과 저장소 사이에서 공통으로 다루는 데이터 형태다. 실제 저장 방식은 저장 상세 설계에서 정한다.

## 문항 기준

| 필드 | 형식 | 역할 |
| --- | --- | --- |
| `id` | 문자열 | 묶음 안에서 문항을 식별하는 값 |
| `question` | 문자열 | 정답을 명확하게 요구하는 질문 |
| `answer` | 문자열 | 대표 정답 하나 |
| `accepted_answers` | 문자열 배열 | 선택 필드. 추가로 정답으로 인정할 표기 |

`accepted_answers`는 생략하거나 빈 배열로 둘 수 있으며, 이 경우 대표 정답만 인정한다. 대표 정답은 배열에 다시 넣지 않아도 항상 인정한다.

## 정답 작성 기준

- 정답은 단답 또는 3~4개 단어로 된 짧은 문장으로 작성한다.
- 대표 정답이나 등록한 허용 표기 중 하나와 완전히 같아야 정답이다. 대소문자와 공백 및 문장부호를 그대로 비교한다.
- 동의어나 약어도 허용 표기로 명시한 경우에만 인정한다. 질문에서 요구하는 답변 형식과 표기를 분명하게 한다.
- 허용 표기도 단답이나 짧은 문장으로 작성한다. 채점에 필요한 정보이므로 문항 본체에 포함한다.
- 긴 개념 설명과 예시는 정답 문자열에 넣지 않고 보충 정보로 분리한다.

## 자료 검증 기준

필수 필드 누락, 빈 질문이나 대표 정답, 묶음 안의 중복 문항 ID는 오류로 안내한다. 허용 표기가 있으면 문자열 배열인지와 각 표기가 비어 있지 않은지 확인한다. 정답과 허용 표기 앞뒤의 불필요한 공백이나 줄바꿈도 작성 오류로 확인하며, 불러오는 과정에서 자동 수정하지 않는다.

## 연결할 설계

비교와 미응답 처리는 [자동 채점 기준](../학습규칙/02_1_자동채점기준.md)을 따른다. 선택적인 설명과 예시는 [보충 정보](01_1_보충정보.md)로 분리하고, 연결 키는 [식별과 관계](03_식별과관계.md)에서 정의한다. 설명형 원문의 재작성은 [문항 작성 기준](04_단답형문항작성.md)과 [자료 변환 절차](04_1_자료변환절차.md)를 따른다.
