# 확장 자료 교환 형식

작성일: 2026-11-26. 수정일: 2026-11-27. 상태: 파서·신규 DB 2 등록·혼합 화면 연결/가상 검증 완료. 기존 DB 1과 배포 exe는 자동 변경하지 않았다. [구현 결과](../../../Window/작업계획/17_혼합시험과평가화면.md)

## 버전과 문항 본체

교환 버전은 `2.0`을 내부 구현 기준으로 사용한다. DB 구조 버전과 별도로 관리한다. `learning.json`의 최상위 필드는 `schema_version`, `dataset_id`, `title`, `items`를 유지한다. 문항은 다음 두 형태 중 하나이며 서로의 평가 필드를 혼합하지 않는다.

| 필드 | 단답형 | 서술형 |
| --- | --- | --- |
| `id`, `question` | 필수 문자열 | 필수 문자열 |
| `type` | `short_answer` | `descriptive` |
| `answer` | 필수 대표 정답 | 허용하지 않음 |
| `accepted_answers` | 생략 시 빈 배열 | 허용하지 않음 |
| `reference_answer` | 허용하지 않음 | 필수 참고 답안 |
| `key_points` | 허용하지 않음 | 비어 있지 않은 문자열 배열 |

참고 답안·핵심 내용은 채점 기준이므로 문항 본체에 둔다. 핵심 내용은 사용자 비교용이며 자동 키워드 채점에 사용하지 않는다. 보충 설명·출처·원문 번호를 본체에 합치지 않는다.

카탈로그도 새 자료를 포함하면 `schema_version=2.0`을 쓴다. 기존 항목의 파일 경로·제목·문항 수 구조를 유지하며, 각 learning 파일은 자기 버전에 따라 읽는다. 따라서 2.0 카탈로그 안에 기존 1.0 묶음과 새 2.0 묶음이 함께 있을 수 있다. 1.0 카탈로그에 2.0 파일을 섞는 것은 거부한다. 보충 파일이 있으면 같은 묶음의 learning 파일과 버전을 맞춘다. 개별 JSON 자료 교환과 전체 카탈로그 배치의 검증 경계를 구분한다.

## 검증과 내부 변환

- `dataset_id`·문항 `id`는 기존 소문자 ID 규칙과 1~64자 제한을 적용한다. 묶음 안의 ID 중복은 거부한다. `source_refs`에는 이 형식 검사를 적용하지 않는다.
- 단답형 정답과 각 허용 표기는 기존 고정 공백 25자·4단어 이하·줄바꿈 거부·정확한 문자열 채점 규칙을 그대로 적용한다.
- 서술형 참고 답안과 각 핵심 내용은 고정 공백 25자만으로 이루어질 수 없다. 여러 줄과 4단어 초과는 허용한다. 문항 질문도 빈 문자열·공백만이면 거부한다.
- 올바르지 않은 UTF-8과 깨진 서로게이트 이스케이프는 거부한다. 유니코드 정규화·공백 정리로 원문을 바꾸지 않는다. U+200B·U+FEFF는 미응답 공백이 아니다.
- `2.0` 본체의 최상위·문항 객체는 허용 필드만 받는다. 알 수 없는 유형·필드·버전과 유형별 기준 누락은 가져오기 전체를 거부한다. 오류는 필드 경로와 코드로 반환하고 값은 로그에 넣지 않는다.
- 확장 파서에는 아래 자원 상한을 적용한다. 문자열 길이는 UTF-8 바이트 기준이다. 4단어 예외를 무제한 메모리 할당으로 해석하지 않는다. 기존 DB 전환에는 새 가져오기 상한을 소급 적용하지 않는다.

| 대상 | 내부 파서 상한 |
| --- | --- |
| JSON 파일 / 한 카탈로그의 읽은 파일 합계 | 16 MiB / 128 MiB |
| 카탈로그 묶음 / 묶음 문항 | 512 / 10,000 |
| 제목 / 질문 | 4,096 / 16,384 바이트 |
| 대표 정답·각 허용 표기 / 허용 표기 수 | 4,096 바이트 / 64개. 별도로 기존 4단어 기준 적용 |
| 서술형 참고 답안 / 각 핵심 내용 / 핵심 내용 수 | 65,536 / 8,192 바이트 / 1~64개 |
| 묶음 연결 레코드 / 레코드별 선행 문항 | 10,000 / 64개 |

Rust 내부에서는 두 유형의 구분 가능한 열거형으로 변환한다. `1.0` 문항은 `short_answer`로만 변환하고 기준 문자열을 그대로 보존한다. `2.0`으로 내보낼 때만 유형을 명시한다. 서술형을 `1.0`으로 내보내는 변환은 제공하지 않는다.

확장 파서의 `1.0` 호환 경로는 기존 자유 필드를 모두 막지 않는다. 대신 문항에 새 유형 전용 `type`, `reference_answer`, `key_points`가 있으면 거부한다. 1.0 카탈로그의 자유 필드도 유지하고 2.0 카탈로그는 허용 필드만 받는다. 기존 DB 1의 등록 경로는 유지하고 신규 DB 2 등록에서 확장 파서를 사용하므로 자료 작성 도구도 반드시 새 버전을 써야 한다.

## 선택 연결 정보

선행 연결은 확장 파서에서 `supplement.json`의 선택 필드 `learning_links`로 읽는다. 기존 `dataset_metadata`와 문항별 자유 보충 내용은 유지한다. 연결은 평가 기준이 아니며 없어도 문항은 유효하다. 활성/비활성 판정은 향후 저장소 연결에서 추가하며 현재 해석기는 제공된 설치 문항의 존재와 연결 그래프를 진단한다.

| 구성 | 후보 필드 |
| --- | --- |
| 연결의 출발 문항 | `item_id` — 같은 묶음의 문항 ID |
| 기초 문항 목록 | `prerequisites` — `{ dataset_id, item_id }` 배열 |
| 학습 단계 안내 | 선택 `stage` — `foundation`, `understanding`, `application` |

연결 외피의 필드·자료형·ID 형식 오류는 보충 파일 검증 오류로 처리한다. 자기 참조·중복·순환·찾을 수 없는 대상은 연결 진단으로 표시하고 해당 연결로 편입하지 않는다. 문항 본체의 유효성과 분리하며 무한 탐색을 하지 않는다. 다른 묶음이 설치되지 않으면 미설치로 안내하고, 설치·갱신 뒤 다시 해석한다. 순환 진단은 현재 설치된 연결 범위 기준이므로 나중에 새 연결이 설치되면 다시 검사한다.

기존 `items`의 자유 보충 내용과 `dataset_metadata`에는 임의의 보충 필드를 허용한다. 본체의 엄격한 검증을 보충 payload 전체에 적용하지 않는다. 참조가 없어도 학습 단계는 출제 잠금이나 정렬 변경 조건이 아니다.

## 출제와 과거 기록

시험 생성 때 유형·질문·유형별 기준·규칙 버전을 스냅샷으로 고정한다. 제출 전 화면에는 유형·질문·자신의 답변만 제공한다. 평가 기준은 제출 처리 성공 후 결과 조회에서만 공개한다.

결과의 기초 연결은 현재 자료의 안내로 표시하며 출제 당시 채점 기준과 혼동하지 않는다. 편입 실행 때 현재 대상의 존재·활성 상태를 다시 검사한다. 자료가 없으면 편입을 실패시키고 실제 응시 기록을 만들지 않는다.

단답형을 서술형으로 바꾸거나 학습 대상이 달라지면 새 문항 ID를 쓴다. 자료 갱신으로 과거 기준·답변·평가를 다시 쓰지 않는다. [유형과 작성 기준](05_문항유형과선행개념.md), [평가 이력](02_4_평가이력.md)
