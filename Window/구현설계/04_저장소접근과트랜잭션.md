# 서비스와 저장소의 접근 계약

상태: 구현 기준. 아래 계약 이름을 Core에 정의하고 Infrastructure에서 구현한다.

## DB 호출 경계

```csharp
interface IStudyDatabase
{
    Task<T> ReadAsync<T>(Func<IReadSession, T> operation, CancellationToken ct);
    Task<T> WriteAsync<T>(Func<IWriteSession, T> operation, CancellationToken ct);
}
```

콜백은 동기식이며 그 안에서 다시 작업 큐를 호출하거나 `await`하지 않는다. Core 서비스는 조회·변경에 필요한 저장소 메서드를 콜백 안에서 조합한다. 연결·SQL·트랜잭션 객체는 Core와 화면에 노출하지 않는다.

| 세션의 저장소 계약 | 읽기 메서드 예와 반환 | 쓰기 세션에서 추가하는 메서드 |
| --- | --- | --- |
| Metadata | `Get(key)` → 문자열 또는 없음 | `Set(key, value)` |
| Learners | `GetLocal()` → 로컬 프로필 | `Insert(learner)` |
| Datasets | `List()`, `LoadActive(orderedIds)` → 자료·문항 모델 | `UpsertPackage(package)`, 기존 문항 비활성화 |
| Exams | `Find(examId)`, `LoadAggregate(examId)`, `List(learnerId)` | `Insert(aggregate)`, `SaveProgress`·`MarkSubmitted`·`MarkCompleted` |
| Progress | `GetForItems(learnerId, keys)`, `ReadCompletedHistory` | `Upsert(state)` |

읽기 세션은 조회 계약만 제공한다. 쓰기 세션은 같은 연결과 트랜잭션에 묶인 조회·변경 계약을 제공한다. `ExamAggregate`에는 내부 채점 스냅샷이 포함되므로 화면 DTO로 직접 반환하지 않는다. 메서드별 입력은 [시험 생성](05_시험생성과조회.md)부터 기능별 흐름에서 정의한다.

## 실행 위치와 수명

`DbWorkQueue` 한 개가 앱 수명 동안 `Channel`의 단일 소비자로 모든 DB 조회·쓰기를 순서대로 수행한다. 작업 소비자는 UI 스레드 밖에서 동기식 SQLite API를 사용하고 `Task`로 결과를 전달한다. 초기 규모에서는 조회도 같은 큐를 사용해 부분 결과 조회를 피한다.

Microsoft.Data.Sqlite의 비동기 ADO.NET 호출은 동기식으로 실행되므로 단순히 `Execute...Async`를 호출하는 것으로 화면 멈춤을 해결하지 않는다. [공식 비동기 제한](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/async)

작업마다 `ConnectionFactory`가 연결을 열고 종료 시 해제한다. `Pooling=False`, `DefaultTimeout=3`을 연결 설정에 두고, 연결 직후 `foreign_keys=ON`, `synchronous=FULL`, `busy_timeout=3000`과 `journal_mode=DELETE`를 적용·확인한다. 별도 command timeout도 3초로 맞춘다. 초기에는 한 작업 큐와 짧은 트랜잭션을 사용하며 WAL을 전제로 하지 않는다.

## 트랜잭션 경계

조회 작업은 `BeginTransaction(deferred: true)`의 읽기 트랜잭션으로 수행한다. 쓰기는 `BeginTransaction(deferred: false)`로 시작하고, 세션의 모든 명령에 같은 트랜잭션을 연결한다. 서비스 콜백 성공 후 COMMIT하고 예외 발생 시 ROLLBACK한다. 반환은 COMMIT 성공 후에만 확정한다. 조회 결과는 세션 안에서 배열이나 모델로 모두 읽어 반환하고 reader·지연 열거·세션 자체를 밖으로 넘기지 않는다. [Microsoft.Data.Sqlite 트랜잭션](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/transactions)

| 작업 | 한 번에 확정할 범위 |
| --- | --- |
| 초기 자료 등록 | 프로필·두 자료와 보충 정보·등록 표시 |
| 자료 갱신 | 갱신 버전 확인·자료·문항·보충 정보·해시와 자료 revision |
| 새 시험 | 조건 확인·후보 선택·자료명과 문항 스냅샷·초기 응답 |
| 진행 저장 | 상태와 revision 확인·답변·위치·저장 시각 |
| 최종 제출 | 최신 답변과 revision·위치·제출 상태와 시각 |
| 시험 완료 | 전체 판정·완료 순번과 상태·영향 문항의 학습 상태 |

파일 읽기·JSON 검증·사용자 확인·내보내기는 DB 트랜잭션 밖에서 수행한다. 가져오기 미리보기와 적용 사이의 자료 변경은 revision 재확인으로 탐지한다. 출제와 오답 집계는 현재 자료 규모의 메모리 계산을 같은 DB 작업 안에서 수행한다.

대기 중 취소는 작업 시작 전에 반영한다. 실행 중인 쓰기는 COMMIT 또는 ROLLBACK을 마친 뒤 상태를 반환한다. COMMIT 후 취소 알림을 실패로 전달해 무조건 재생성하지 않는다. 통신이 아닌 로컬 요청에서도 완료 여부가 불분명하면 같은 ID로 상태를 조회한다.

## 저장 코드 공통 규칙

문자열은 parameter로 바인딩하고 원문을 보존한다. 갱신은 `ON CONFLICT ... DO UPDATE`를 사용하고 참조 행을 삭제할 수 있는 `INSERT OR REPLACE`를 사용하지 않는다. 연결과 transaction은 세션 종료 후 재사용하지 않는다.

저장 실패는 [화면 연결](09_화면연결과오류처리.md)의 오류 코드로 변환한다. 단순 재조회는 학습 상태를 쓰지 않으며, 모든 변경은 위 쓰기 경계를 거친다.
