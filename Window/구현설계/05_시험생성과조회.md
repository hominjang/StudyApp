# 시험 생성과 자료 조회 연결

상태: 일반·오답 우선·오답만 시험, 후보 수 미리보기와 전체 기록·필터·결과 조회 및 재개 구현. 화면은 DTO만 사용하고 DB나 정답 모델을 직접 받지 않는다.

## 자료 목록과 후보 수

React 자료 hook이 list_datasets 명령으로 Rust DatasetService를 호출한다. 서비스는 DB 읽기 작업 안에서 자료명과 활성 문항 수를 조회하고 `DatasetSummary` 배열을 반환한다. 원본 JSON을 다시 읽지 않는다.

선택 변경 시 `PreviewCandidatesAsync(settings)`가 로컬 프로필의 `item_progress`와 활성 문항을 결합해 가능한 문항 수를 반환한다. 이 결과는 설정 안내용이며 시작 시 다시 확인한다. 연속 요청은 요청 번호로 구분해 현재 선택과 다른 과거 결과를 화면에 적용하지 않는다.

preview_candidates는 순서 있는 dataset_ids와 review_mode를 받고 candidate_count·total_count·review_target_count를 반환한다. React는 자료·모드·갱신 세대로 요청을 구분하며 과거 응답을 적용하지 않는다. start_exam은 쓰기 트랜잭션에서 범위와 개수를 다시 확인한다.

## 시험 생성 계약

| 항목 | 내용 |
| --- | --- |
| 호출 | `start_exam` → Rust ExamService의 StartExamRequest 처리 |
| 입력 | 미리 생성한 `exam_id`, 순서 있는 `dataset_ids`, `count_mode`, 개수 지정일 때의 `count`, `order_mode`, `review_mode` |
| 프로필 | 시작 시 주입한 `LocalStudyContext`. 화면 입력에서 learner_id를 받지 않음 |
| 성공 반환 | `ExamSessionDto`: 시험 ID·revision·현재 위치·문항별 위치/출처 키/질문/입력 답변과 표시용 설정 |
| 실패 반환 | 자료 없음·후보 없음·개수 오류·저장 실패와 수정할 입력 정보 |

`ExamSessionDto`에는 대표 정답·허용 표기·해설·정답 판정을 포함하지 않는다.

## 하나의 쓰기 작업에서 수행할 순서

1. 같은 시험 ID가 있으면 프로필과 요청 설정이 같은지 검사한다. 같으면 기존 상태로 반환하고 다시 추출하지 않으며, 다르면 충돌로 종료한다.
2. 선택한 자료를 선택 순서와 문항 position 순서로 읽고 현재 학습 상태를 결합한다.
3. `QuestionSelector`가 모드별 후보에서 전체 또는 지정 수를 중복 없이 선택하고 최종 표시 순서를 정한다. 무작위 공급원은 주입해 규칙 테스트에서 제어한다.
4. 자료명과 질문·대표 정답·허용 표기를 복사해 시험과 전체 응답을 생성한다. `status=in_progress`, `revision=0`, 위치 `0`, 답변 `""`, 판정 `ungraded`, 규칙 `exact-v1`로 시작한다.
5. COMMIT 후 작성용 DTO를 반환한다. 화면은 이 시점에만 시험으로 이동한다.

무작위 결과를 복원하기 위한 재추출은 하지 않는다. 실제 선택과 순서가 `exam_responses.position`에 저장된다. 선택 규칙은 [재출제](<../../공통 개발 문서/상세설계/학습규칙/04_재출제.md>)를 따른다.

시작 버튼은 처리 중 비활성화하고 저장 오류 뒤 재시도에서도 같은 시험 ID를 유지한다. 설정을 바꿔 새 시작을 시도하면 새 ID를 생성한다. 성공 여부가 불분명한 요청은 기존 ID 조회로 확인해 중복 시험을 만들지 않는다.

## 기록과 결과 조회

`ExamQueryService.ListHistoryAsync(filter)`는 저장된 자료명을 사용해 시험 상태·문항 수·저장/완료 시각을 반환한다. 미완료에는 점수를 반환하지 않는다. 완료 목록은 완료 순번의 내림차순, 미완료 목록은 saved_at 내림차순으로 표시한다.

`ResumeAsync(examId)`는 해당 시험의 저장된 상태를 읽어 작성 화면·처리 화면·완료 결과 중 하나로 분기한다. `GetResultAsync(examId)`는 완료 시험에만 정답 스냅샷을 포함한 결과 DTO를 반환한다. 두 조회 모두 Rust 상태에 보존한 로컬 프로필 소유 여부와 응답 수·위치의 일관성을 확인하며, 불일치 시 새 시험으로 대체하지 않는다.

결과의 정답 비율은 확정 응답에서 계산하고 저장된 응시 판정은 수정하지 않는다. 현재 오답 상태와 해설은 별도 최신 조회 값으로 결합한다. [제출과 결과](07_제출채점과결과.md)에서 집계 경계를 정의한다.

현재 list_exam_history의 filter는 all·in_progress·submitted·completed다. 전체 목록은 미완료를 saved_at 내림차순으로 먼저 표시하고 완료는 completion_order 내림차순으로 표시한다. 미완료에는 correct_count를 반환하지 않으며, 목록에는 질문·정답·입력 답변을 포함하지 않는다. 읽지 못한 시험은 원래 정렬 위치에 `error`가 있는 행으로 반환하고, 나머지 기록은 그대로 조회한다.

서비스의 Async 메서드 표기는 사용 사례의 책임을 나타낸다. 실제 React 호출은 [Rust 명령 표](09_화면연결과오류처리.md)를 사용한다. 시험 저장·결과는 storage/exams.rs, 후보 수·기록 조회는 storage/history.rs, 모드별 선택은 exam.rs에 구현했다. [5단계 검증 결과](../작업계획/10_기록조회와오답재학습.md)
