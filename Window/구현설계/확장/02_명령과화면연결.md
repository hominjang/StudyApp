# 확장 명령과 화면 연결

작성일: 2026-11-26. 상태: 현행 목록 DTO와 DB 2 평가/복습 명령·Worker·bridge 구현. DB 2 시험 저장소·혼합 UI·기초 연결·평가 대기 필터까지 연결했다. [상태 정책 초안](<../../../공통 개발 문서/상세설계/학습규칙/02_3_평가상태와재계산.md>) 을 검증한 백엔드이며 활성 적용 전 정책 검토는 남아 있다.

## 파일과 책임

현재 구현의 실제 조회 명령은 `get_assessment_view`이며 `AssessmentView`의 `counts`, `assessment_status`, `result_revision`과 응답별 최초/현재 평가·평가 revision·현재 복습 상태/집계 revision을 반환한다. 쓰기 명령은 `set_response_assessment`, `add_review_target`이다. `assessment.rs` → DbWorker → `lib.rs` 등록 → `bridge/assessment.ts`까지 연결했다. 선택 사유 `note`는 UTF-8 2,048바이트 이하, 요청 ID는 소문자 하이픈 UUID v4다.

현행 목록의 정상/오류 합집합은 `desktop.ts`에 반영했다. 혼합 시험·기초 연결·목록의 평가 대기 필터도 구현했다. DB 1은 새 평가 명령에서 `UnsupportedDbVersion`으로 거부하며 DB를 자동 전환하지 않는다. [구현 결과](../../작업계획/16_손상기록과평가명령.md)

`package.rs`·`validation.rs`에서 버전과 문항을 검증하고 내부 유형으로 변환한다. `exam.rs`는 DTO와 평가 상태, `storage`는 스냅샷·평가 이력·집계·멱등 처리를 맡는다. `worker.rs`와 `lib.rs`는 동일한 계약을 전달하고 `desktop.ts`가 화면의 유일한 invoke 경계가 된다. 화면은 정답 판정이나 DB 재계산을 대신하지 않는다.

| 명령 | 요청/응답의 변경 후보 | 화면 동작 |
| --- | --- | --- |
| `start_exam`, `get_exam_session` | SessionItem에 `type` 추가. 기준 필드는 없음 | 단답형 한 줄, 서술형 여러 줄. 기존 여러 줄 단답형은 원문 복원 보완 유지 |
| `save_progress`, `submit_exam` | 현재 응답/위치/revision 계약 유지 | 고정 공백 25자로 미응답 안내. Enter·한글 조합으로 자동 제출하지 않음 |
| `complete_exam` | 단답형/미응답 자동 판정, 응답 있는 서술형은 미평가로 완료 | 시스템 실패는 같은 시험 재시도. 사용자 평가 대기와 구분 |
| `get_exam_result`(DB 1) / `get_assessment_view`(DB 2) | 유형별 기준, 최초/현재 평가, 평가 revision, 네 개수, 평가 진행 상태 | 제출 처리 성공 후에만 공개. 점수 환산 없이 개수 표시 |
| `set_response_assessment` — DB 2 구현 | `exam_id`, `position`, `expected_revision`, `judgement`, 선택 사유, `request_id` | 선택을 서버 성공 전 확정 표시하지 않음. 실패 시 입력/기존 평가 유지 |
| `add_review_target` — DB 2 구현 | `dataset_id`, `item_id`, `expected_progress_revision`, `request_id` | 모르는 기초 문항을 복습 지정. 중복이면 추가됨 상태만 반환 |
| `list_exam_history`, `list_pending_exams` | 정상/오류 합집합과 `row_key`는 구현. DB 2 평가 진행 필터도 구현 | 손상 행 열기 금지. 미평가 시험은 결과에서 평가 이어 하기 |
| `preview_candidates`, `list_datasets` | 수동 지정이 반영된 대상 수와 현재 집계 revision | 기존 자료 선택 범위와 일반/오답 우선/오답만 유지 |
| `get_foundation_links` — DB 2 구현 | `exam_id`, `position` → 해당 응답에서 출발한 현재 연결 대상의 ID·질문·설치/활성/진단·학습 상태 revision | 결과·회고에서만 안내. 정답/참고 답안은 반환하지 않음 |

판정 요청은 `correct | partial | incorrect` 중 하나다. 사유는 감사용 선택 문자열이며 답변 원문을 수정하는 필드가 아니다. 요청의 사용자 ID는 화면 값으로 신뢰하지 않고 현재 로컬 프로필에서 가져온다. 평가 대상이 그 프로필의 완료 시험인지 검사한다. 미응답 정정 거부 등 미확정 정책은 공통 권장안 기준의 조건부 계약이다.

연결 조회는 완료 시험과 응답 위치를 확인한 결과 화면에서 호출한다. 반환 값의 단독 질문으로 미공개 기준을 유추하게 보충 payload 전체를 내보내지 않는다. 원래 문항 기준은 당시 스냅샷이고 기초 연결은 현재 자료 안내라는 표시를 구분한다.

## 응답과 버전

`ExamResult`는 `assessment_status`, `assessment_counts`, `result_revision`을 갖는 안이다. counts는 correct/partial/incorrect/ungraded 네 값이고, 미응답 수는 별도 하위 통계다. 각 응답은 최초 평가·현재 평가·변경 여부·`assessment_revision`을 갖는다. 학습 상태는 현재 시점 값으로 표시하며 과거 판정과 구분한다.

시험 `result_revision`은 유효 평가가 바뀔 때 증가한다. 개별 평가는 자기 응답 revision으로 충돌을 판단하므로 다른 문항을 평가한 것만으로 저장을 거부하지 않는다. 갱신 성공 후 전체 결과를 다시 읽어 개수와 평가 상태를 일치시킨다. 결과 조회는 한 DB 읽기 스냅샷 안에서 처리한다.

신규 쓰기 반환은 `saved | already_applied | unchanged`와 식별자·새 revision을 갖는다. 공통 오류 외에 `AssessmentConflict`, `ProgressConflict`, `RequestConflict`, `AssessmentNotAllowed`, `LinkedItemUnavailable`, `ProgressSourceCorrupt`를 구분하는 안이다. 오류는 사용자용 설명·필드 경로·재시도 가능 여부만 제공하고 원문은 넣지 않는다.

학습 상태가 아직 없는 문항의 `progress_revision`은 0으로 반환한다. 상태가 생성되거나 원천 변경이 반영되면 증가시키되 같은 요청 재시도·변경 없음 응답에서는 증가시키지 않는다. 기반 상태가 바뀐 편입 요청은 재조회 후 사용자가 다시 실행한다.

목록 DTO는 정상 행과 오류 행의 구분 가능한 합집합으로 구현했다. 정상 행은 기존 필수 정보를 갖고, 오류 행은 `kind=error`, `row_key`와 안내만 갖는다. 읽지 못한 문항 수·상태·ID에 0이나 임의의 정상 값을 채우지 않는다. 필터 상태조차 모르는 행은 전체 기록에만 포함한다.

## 요청 유실·충돌·재조회

1. 화면은 사용자의 저장 동작마다 요청 ID를 한 번 만들고, 결과가 불명확한 네트워크/프로세스 응답 유실 재시도에는 같은 내용과 ID를 유지한다.
2. 다른 내용으로 바꾸면 새 요청 ID를 쓰고 최신 revision을 확인한다. 충돌 시 자동 덮어쓰기하지 않고 최신 평가와 사용자의 미저장 선택을 함께 안내한다.
3. 성공 뒤 결과·기록 요약·자료별 대상 수를 무효화하고 다시 조회한다. 읽기 실패 시 저장 실패라고 단정하지 말고 저장 상태 확인 중으로 안내한다.
4. 화면 재실행으로 요청 ID를 잃었으면 먼저 DB의 현재 결과를 조회한다. 동일 판정은 변경 없음, 이미 복습 대상인 문항은 중복 편입 없음으로 처리한다.

자료 선택 설정은 결과 보기·평가·수동 편입만으로 덮어쓰지 않는다. 기초 문항이 다른 묶음에 있어도 자동으로 시험 범위를 확장하지 않는다. 다음 시험의 선택 범위 안에서만 기존 오답 출제에 반영한다.

## 화면 검증 경계

서술형 textarea는 Enter·CR/LF 붙여 넣기·IME 조합을 자동 저장하되 제출 버튼만 최종 제출을 시작한다. 저장된 원문을 공백 정리나 정규화로 바꾸지 않는다. 기존 CR/CRLF 복원 로직과 새 서술형 입력의 공통 사용 여부는 실제 브라우저 정규화와 원문 보존 테스트로 판단한다.

브라우저 미리보기는 저장 성공을 흉내 내 실제 구현으로 보고하지 않는다. DB 없는 상태 안내를 유지한다. 실제 IME·클립보드·종료 후 재개는 Windows 앱에서 별도 검증한다. [전환과 검증](03_전환과검증.md)
