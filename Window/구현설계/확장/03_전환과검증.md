# 기존 자료·기록 전환과 검증

작성일: 2026-11-26. 상태: 확장 파서·DB 사본 전환 구현과 가상 검증 완료. DB 2 평가 명령은 후속 구현했고 활성 DB 교체·실제 자료 전환은 미실행이다. [구현 결과](../../작업계획/15_확장파서와전환기반.md)

## 현재 구현한 안전 경계

`prepare_v2_copy(source, destination)`는 원본을 읽기 전용으로 열고 SQLite Backup API로 새 임시 사본을 만든다. 그 사본만 트랜잭션으로 전환·재조회 검증한 뒤 새 경로로 확정한다. 원본과 기존 목적지는 덮어쓰지 않는다. 원본 버전 1·설치 완료 표시·프로필·무결성·기준·판정·완료 순서와 학습 집계의 일치를 확인하며 미완료 응답은 미평가로 보존한다.

사본 생성은 최대 10초 내에서 재시도하고, 실패한 임시 파일은 정상 반환 경로에서 정리한다. 강제 종료 시 남을 수 있는 임시 파일의 발견/정리와 실제 디스크 부족은 아직 검증하지 않았다. 사본을 만든 뒤에도 원본에 새 기록이 생길 수 있으므로 나중 활성 전환에서는 원본 쓰기 중단·최종 사본 확인을 다시 해야 한다.

이 API는 앱 시작이나 Tauri 명령에서 호출하지 않는다. 아래 전체 전환 절차 중 활성 DB 교체·복원 안내는 후속 구현이며, 구형 Store는 DB 1만 열고 앱의 RuntimeStore가 DB 2 사본도 구분해 정상 연결한다. 재전환도 같은 오류로 거부하고 이력을 중복 생성하지 않는다.

## 활성 전환까지의 목표 절차

교환 버전 `2.0`과 별개로 DB 사본의 구조 버전 `1 → 2`를 구현했다. 기존 원본 `V001_Initial.sql`을 수정하지 않고 새 전환을 추가한다. 구형 앱은 새 DB를 지원하지 않는다고 거부해야 하며 다시 초기화해서는 안 된다.

1. 앱의 DB 작업을 중단하고 연결을 독점한다. `application_id`·버전·무결성·외래 키와 전환 가능한 필수 값을 검사한다. 손상된 원본을 고치면서 전환하지 않는다.
2. SQLite의 일관된 백업 방식으로 별도 로컬 보존본을 만들고 무결성을 검사한다. 열린 DB 본체만 복사하지 않는다. DB·WAL·SHM 경계와 디스크 부족을 포함해 실패를 다룬다. 백업은 실제 기록이므로 Git/로그에서 제외한다.
3. 트랜잭션 안에서 새 테이블과 제약을 만들고 데이터를 옮긴다. 제약 변경이 필요한 기존 테이블은 재구축하며 기본/외래 키와 인덱스를 다시 확인한다.
4. 기존 문항·시험 스냅샷은 단답형으로만 매핑한다. ID·응답 원문·기준·상태·revision·시각·완료 순번을 보존한다. 진행 중/제출 처리 대기에 최초 평가나 완료 순번을 새로 만들지 않는다.
5. 완료 응답마다 기존 자동 판정 하나를 최초 이력과 현재 평가로 연결한다. 완료 시험은 기존 완료 순번 순으로 `learning_events`의 순서를 정한다. 사용자가 같으면 원래 순서가 반드시 보존되어야 한다.
6. 새 원천으로 학습 상태를 재계산하고 기존 대상·연속 횟수와 비교한다. 원천이 없는 기존 학습 상태 등 불일치가 있으면 임의로 수동 편입이나 응시를 생성하지 말고 전환을 실패시킨다.
7. 행 수·원문 동일성·스냅샷·유일 키·이력 연결·집계 일치와 외래 키를 검사한 뒤 DB 버전 메타데이터를 마지막에 바꾸고 커밋한다. 성공 후 다시 열어 확인한다.

트랜잭션 중 실패는 전체 롤백하고 버전 1 원본을 유지한다. 커밋 뒤 재검증에 실패하면 쓰기를 차단하고 닫힌 DB를 보존한 뒤 검증된 보존본으로 복구하는 절차를 제공한다. 자동으로 초기 DB를 덮어쓰지 않는다. 프로세스 중단 후 재실행은 버전과 전환 표식을 보고 완료/미완료를 판별하며 동일 이력을 두 번 생성하지 않는다.

개발 DB와 release DB를 자동 복사하지 않는다. 가상 DB에서 모든 전환 실패 경로를 검증하기 전 실제 사용자 DB에 새 앱을 연결하지 않는다. 이번 작업은 실제 DB 조회·복사도 수행하지 않는다.

## 구현 순서와 선행 조건

현재는 파서/사본 전환에 이어 기본 열 목록 격리와 DB 2 평가/복습 명령·원자적 재계산까지 가상 검증했다. 아래 순서 중 DB 2 자료/시험 저장소와 혼합 UI도 가상 검증했고 기존 사용자 DB의 활성 교체는 남아 있다. [후속 결과](../../작업계획/16_손상기록과평가명령.md)

| 순서 | 작업 | 다음 단계로 가는 조건 |
| --- | --- | --- |
| 1 | 남은 정책 권장안 검토, 필드/버전·자원 상한 고정 | 공통과 Windows 계약 간 미정 표현 해소 |
| 2 | 1.0/2.0 파서·내부 유형·기준 검증 | 잘못된 새 유형을 단답형으로 읽지 않음 |
| 3 | 기본 열 오류까지 목록 격리, 집계 손상 정책 구현 | 정상 목록 유지·손상 원천의 조용한 생략 없음 |
| 4 | DB v2 전환·평가/복습 이벤트와 재계산 구현 | 가상 DB 전환·실패 롤백·원문/기록 보존 통과 |
| 5 | 명령/DTO·혼합 시험·평가/정정·기초 편입 화면 | 응답 유실·충돌·재실행과 상태 공개 검증 통과 |
| 6 | 제한된 실제 자료 보강·Windows 직접 확인·새 exe | 가상 회귀와 사용자 확인 뒤 실제 데이터 범위 확대 |

이는 확장 2·3에 걸친 구현 순서다. 파서·사본 전환 검증만으로 앱 전체 지원 완료로 표시하지 않는다. 평가 정책이 미정이어도 자료 형식 검토는 할 수 있지만 정책에 의존하는 집계 구현은 먼저 고정하지 않는다.

| 영역 | 필수 사례와 확인할 결과 |
| --- | --- |
| 자료 | 기존 1.0 그대로 읽기, 새 두 유형/혼합, 알 수 없는 버전/유형·잘못 섞인 필드 거부, 보충 자유 필드 허용 |
| 문자열 | 4/5단어와 25자 경계, 서술형 4단어 초과/여러 줄 허용·빈 기준 거부, 깨진 유니코드 거부, 입력 원문 보존 |
| 연결 | 미설치·삭제·비활성·자기/순환/중복 연결 진단, 설치 후 다시 해석, 현재 시험 문항 수·순서 불변 |
| 평가 | 단답형만·서술형만·혼합, 미평가와 처리 실패 구분, 최종 제출 전 기준 비공개, 네 개수 합계 |
| 이력 | 최초 자동 판정 보존, 응답별 정정, 오래된 revision 거부, 같은 요청 재시도/다른 내용 거부, 중간 실패 롤백 |
| 재계산 | 과거 정정·늦은 평가 뒤 이후 시도 재반영, 부분/미평가 정책, 수동 편입 전후·해제/재편입, 같은 item_id의 묶음별 분리 |
| 손상 | ID/상태/시각/완료 순번 기본 열 오류 격리·안정 정렬, 손상 원천과 같은 문항 쓰기 차단·다른 문항 유지 |
| 전환 | 빈 DB/기존 완료/진행 중/제출 대기, CR/CRLF 포함 원문 보존, 디스크/제약/중간 중단 실패, 재실행·재전환 멱등 |
| 화면 | 실제 IME 조합 중 Enter·붙여 넣기·여러 줄·자동 저장/종료/재개, 평가 후 다른 화면 개수 갱신·시작 설정 유지 |

테스트 데이터는 직접 만든 가상 값만 사용하고 실제 자료를 fixture로 옮기지 않는다. 검사 결과에는 사례 수·통과 여부·오류 코드만 남긴다. 순수 모델·앱 코드·실제 Windows 조작을 나눠 기록한다. 기존 실제 자료용 ignored 테스트와 한글 IME 검증은 실행 전까지 미확인이다.
