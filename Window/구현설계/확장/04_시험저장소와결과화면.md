# DB 2 시험 저장소와 혼합 결과 화면

작성일: 2026-11-27. 상태: 구현·가상 전체 흐름·Windows 창 검증 완료. 기존 사용자 DB의 활성 전환과 새 배포 exe는 아직 적용하지 않았다.

## 시작과 저장소 선택

`RuntimeStore::open`은 기존 파일의 버전을 읽고 DB 1이면 기존 Store, DB 2면 AssessmentStore로 연결한다. 버전을 추정하거나 기존 파일을 덮어쓰지 않는다. 저장소가 없는 신규 환경은 1.0/2.0 카탈로그를 검증한 뒤 DB 2로 초기화한다.

새 DB는 임시 파일에 빈 V001 구조와 프로필을 만들고 V002로 전환한 뒤 자료·보충·선행 연결을 등록한다. 무결성 확인 후에만 `study.db`로 확정한다. 자료 오류·트랜잭션 실패 시 부분 등록된 DB를 정상 저장소로 내보내지 않는다. 자료 해시는 학습 본체·보충 내용·선행 연결을 함께 포함한다. 기존 사용자 DB 1은 자동 전환하지 않는다.

## 생성·저장·최종 제출

시험 생성은 현재 자료·후보를 다시 확인하고 유형·질문·평가 기준을 스냅샷으로 고정한다. 같은 시험 ID와 같은 설정의 재시도는 기존 시험을 반환한다. 선택 범위·개수·정렬과 오답 우선/오답만 규칙은 유지한다. 세션 DTO의 `db_version`·`item_type`은 화면 분기용이고 정답·참고 답안·핵심 내용은 포함하지 않는다.

DB 2에서도 답변 revision·500ms/2초 자동 저장·제출 잠금을 유지한다. 같은 버전의 다른 답변은 충돌, 오래된 저장은 stale, 제출 후 저장은 locked다. 단답형은 기존 한 줄/과거 여러 줄 복원, 서술형은 처음부터 여러 줄 편집을 사용한다. 텍스트 원문을 임의로 정리하거나 정규화하지 않는다.

최종 제출 후 자동 완료는 단답형을 완전 일치로 판정하고, 응답 있는 서술형은 미평가로 둔다. 고정 공백 25자만인 미응답은 유형과 관계없이 오답이다. 완료 순번·학습 이벤트·자동 평가 이력·현재 평가·문항 집계를 한 트랜잭션으로 저장한다. 손상 원천이나 중간 실패 시 시험을 부분 완료하지 않는다. 완료 재시도는 새 시도나 평가를 만들지 않는다.

## 평가·회고와 기초 복습

DB 2 완료 결과는 `get_assessment_view`로 읽고 네 평가 개수를 표시한다. 기록의 `assessment_pending` 필터에서 미평가 시험을 다시 열 수 있다. DB 1 결과의 기존 표시와 호환 경로는 유지한다.

평가 버튼은 요청 ID와 확인한 평가 revision을 함께 보낸다. 응답을 확정할 때까지 다른 평가·이동을 막고, 실패하면 같은 요청으로 재시도하거나 최신 결과를 읽어 상태를 확인한다. 종료 전에도 실행 중 작업과 미확인 요청을 검사한다. 평가 정정은 제출 원문·당시 기준·최초 평가를 바꾸지 않는다.

연결된 기초 문항은 완료 결과에서 명시적으로 조회한다. 현재 설치된 활성 문항의 질문·연결 진단·복습 상태만 반환하고 정답은 반환하지 않는다. 없는 대상·비활성·중복·자기/순환 연결은 추가를 제한한다. 수동 추가는 별도 학습 이벤트이며 상위 문항 판정·시험 문항 수·응시 횟수를 바꾸지 않는다. 이후 선택한 범위의 기존 오답 우선/오답만으로 복습한다.

## 적용 경계

현재 DB 2 동작은 권장 정책의 구현과 검증이다. 사용자 확정 이력과 구분하며 기존 사용자 DB 전환·실제 자료 보강·배포 적용 전 정책을 함께 점검한다. 실제 한글 IME 조합·클립보드·큰 이력 성능과 활성 교체/복원은 남은 검증이다. [구현 결과와 검사](../../작업계획/17_혼합시험과평가화면.md)
