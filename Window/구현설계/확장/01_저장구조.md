# 확장 데이터와 기록 저장 구조

작성일: 2026-11-26. 상태: DB v2 사본 전환 기반 구현·가상 검증 완료. [공통 정책 권장안](<../../../공통 개발 문서/상세설계/학습규칙/02_3_평가상태와재계산.md>)을 검증하는 DB 2 평가/복습 쓰기·재계산을 구현했다. 활성 적용 전 정책 검토는 남아 있다. 현재 V001 SQL과 앱의 버전 1 저장 경로는 유지한다.

실제 DDL은 [V002](../../src-tauri/migrations/V002_Extension.sql), 사본 전환 API는 [migration.rs](../../src-tauri/src/migration.rs)다. 새 테이블·원천 이력과 기존 판정의 최초 이력 연결을 구현했지만, 평가/수동 편입 명령은 구현했고 DB 2 시험 저장소와 UI도 연결했고 가상 Windows 검증을 마쳤다. [구현 결과](../../작업계획/15_확장파서와전환기반.md)

## 저장 책임과 연결

DB 2 서비스의 평가/정정·수동 편입·원천 검증/재계산은 [assessment.rs](../../src-tauri/src/assessment.rs)와 [progress.rs](../../src-tauri/src/assessment/progress.rs)에 구현했다. 개수는 결과 조회 트랜잭션에서 유효 평가로 계산하며 별도 개수 캐시를 두지 않는다. 쓰기는 이력·현재 평가·시험 결과 revision·문항 집계·성공 요청 기록을 원자적으로 저장한다. 새 시험 생성·자동 완료도 같은 DB 2 원천/집계 계약에 연결했다.

| 저장 단위 | 키와 주요 내용 | 원천/파생 구분 |
| --- | --- | --- |
| `items` | `(dataset_id, item_id)`, 위치·유형·질문·`criteria_json`·활성 여부 | 현재 학습 자료. 기준 JSON은 유형별 열거형으로 검증 |
| `item_learning_links` | 출발/대상 묶음·문항 키, 표시 순서·학습 단계 | 선택 연결. 대상 미설치는 허용하고 조회 때 진단 |
| `exam_responses` | `(exam_id, position)`, 식별 키·유형·질문·기준 스냅샷·원문 답변 | 출제/응답 원본. 제출 뒤 불변 |
| `assessment_events` | `event_id`, 응답 키, 응답별 순번, 이전/이후 판정, 방식·시각·선택 사유·`request_id` | 추가 전용 최초 평가/정정 이력 |
| `response_assessments` | 응답 키, 현재 판정·사유, 최신 이벤트·`assessment_revision` | 이력으로 복원 가능한 현재 평가 |
| `learning_events` | 사용자·`event_seq`, 종류, 실제 시험 또는 수동 편입 키 | 집계 순서의 원천. 사용자의 순번은 유일 |
| `item_progress` | 사용자·묶음·문항, 대상 여부·연속 횟수·마지막 실제 결과/시험, `progress_revision` | 원천 순서와 최신 평가로 재계산한 캐시 |
| `mutation_requests` | 사용자·`request_id`, 명령 종류·요청 해시·저장 결과 | 성공 요청 재시도 중복 방지. 답변 원문을 요청 로그로 복제하지 않음 |

`event_id`·`request_id`도 앱이 생성하는 소문자 하이픈 UUID v4를 쓰는 기술 제안이다. 기존 exam/learner ID의 확정 규칙은 그대로 적용한다. 모든 문항 연결은 묶음과 문항의 조합이며 문항 ID 하나로 연결하지 않는다.

수동 편입은 `learning_events.kind=manual_review_add`로 보존한다. 실제 시험은 시험당 하나의 `exam_attempt` 이벤트로 응답 전체와 연결한다. `(learner_id, event_seq)`는 유일하고 완료 시험당 실제 시도 이벤트도 하나다. 같은 문항의 유효한 수동 편입 재시도는 새 이벤트를 만들지 않는다.

수동 편입만 있고 응시가 없는 `item_progress`의 `last_result`, `last_completed_exam_id`는 NULL을 허용한다. 기존 NOT NULL 제약을 더미 값으로 통과시키지 않는다. 마지막 실제 결과는 최신 유효 평가 중 미평가를 제외한 실제 응시에서만 가져오며, 수동 이벤트는 오답 횟수 통계에 들어가지 않는다.

## 판정과 제약

현재 판정 후보는 `ungraded | correct | partial | incorrect`다. `incorrect_reason`은 자동 미일치·미응답·사용자 판정을 구분한다. `ungraded`는 사용자 평가 전 상태이므로 최초 평가 이벤트를 만들지 않아도 된다. 서술형 미응답은 최초 자동 오답 이벤트를 만든다. 기존 자동 결과는 전환 이력으로 연결하고 보존한다.

최초 자동 판정은 이후 사용자 평가로 수정하지 않는다. 응답별 첫 유효 평가 이벤트와 최신 이벤트를 구분해 조회한다. 이전 판정과 새 판정이 같고 사유 변경도 없으면 변경 없음으로 반환하고 revision을 올리지 않는다. 판정 없는 상태로 되돌리기는 권장안의 초기 범위 밖이다.

기준 스냅샷은 단답형이면 정답/허용 표기, 서술형이면 참고 답안/핵심 내용만 갖는다. DB 로드에서도 동일한 열거형 검증을 한다. 알 수 없는 유형·형식의 JSON을 화면에 그대로 전달하지 않는다. 현재 자료가 삭제되거나 비활성이 되어도 과거 스냅샷을 보존한다.

## 트랜잭션 경계

모든 쓰기는 기존 단일 DbWorker를 통해 실행한다. 화면이 순번·정답 판정·현재 학습 상태를 계산해 DB에 직접 전달하지 않는다.

| 쓰기 | 한 트랜잭션으로 저장할 것 |
| --- | --- |
| 시험 생성 | 자료/후보 재검증·출제 스냅샷·초기 빈 응답 |
| 제출 잠금 | 최신 진행 revision 검사·최종 원문·상태/시각. 제출 전 기준은 계속 비공개 |
| 자동 완료 | 완료 순번·학습 이벤트 순번·자동 평가 이력/현재 평가·시험 개수·관련 학습 상태·완료 표시 |
| 사용자 평가/정정 | 멱등 요청 검사·응답 평가 revision 검사·이력/현재 평가·전체 개수·관련 문항의 이후 이력 재계산·요청 결과 |
| 수동 복습 편입 | 대상 존재/활성 재검증·학습 상태 revision 검사·편입 이벤트·재계산·요청 결과 |

트랜잭션 안에서 사용자별 다음 순번을 할당하고 유일 제약을 둔다. 쓰기 중 실패하면 순번을 포함해 전체 롤백한다. 기존 응답 revision은 자동 저장 충돌용이고, 평가 revision과 학습 상태 revision은 별도로 관리한다.

`mutation_requests`는 같은 요청 ID·같은 내용이면 원래 성공 결과를 반환한다. 같은 ID에 다른 내용이면 `RequestConflict`로 거부한다. 이미 성공한 요청의 재시도 검사를 현재 revision 검사보다 먼저 수행한다. 반환 뒤 화면은 최신 결과를 재조회하므로 재시도 시점의 오래된 개수를 화면에 고정하지 않는다.

## 목록과 손상 범위

기본 열을 전체 `collect<Result>`로 읽은 뒤 격리하지 않는다. 각 원시 행을 독립적으로 해석하고 기본 열 오류도 행별 진단으로 반환한다. ID를 읽지 못한 행은 내부 행 위치에서 만든 불투명 `row_key`로만 식별하고 열기 버튼을 제공하지 않는다. 오류에 DB 원문을 싣지 않는다.

권장 정렬은 정상 미완료(저장 시각 내림차순) → 정상 완료(완료 순번 내림차순) → 손상 행이다. 동률은 읽을 수 있는 ID, 손상 행은 내부 행 순서로 고정한다. 상태를 읽을 수 없는 오류 행은 전체 기록에서만 보여 주고, 자료 목록과 미완료 목록의 실패는 서로 전파하지 않는다.

손상된 학습 원천이 있으면 영향 문항을 포함한 완료·평가·편입 트랜잭션을 차단하는 권장안을 따른다. 목록 격리와 집계 건너뛰기는 같은 기능이 아니다. [전환과 검증](03_전환과검증.md)
