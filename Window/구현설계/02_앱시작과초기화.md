# 앱 시작과 초기화

상태: 단일 실행 관리·로컬 경로 결정·초기 등록·자료 목록 연결 구현. DB migration·백업·복구는 이후 단계다.

| 순서 | 담당 | 처리 |
| --- | --- | --- |
| 1 | Tauri 실행점과 단일 실행 관리 | 같은 로컬 사용자의 중복 실행을 차단하고 기본 창 준비 |
| 2 | infrastructure의 AppPaths | 패키지 resource_dir의 initial-data와 Windows LOCALAPPDATA/StudyApp 경로 결정 |
| 3 | application 초기화 조정 | DB 존재·앱 식별·구조 버전을 검사하고 필요 시 백업·migration |
| 4 | InitialDataService | 알려진 미등록 구조에 초기 자료·로컬 프로필·반영 표시를 한 번에 등록 |
| 5 | AppState와 DB 작업 큐 | 보존된 learner_id와 저장소 핸들을 Rust 상태에 유지 |
| 6 | React의 앱 상태 요청 | 초기화 성공 후 list_datasets를 요청해 첫 화면 표시 |

무거운 초기화는 첫 get_app_status 요청 시 전용 DB 스레드에서 수행하며 UI와 Tauri 이벤트 스레드를 막지 않는다. 초기화 중에는 시험·자료 변경 명령을 거부하고 상태 조회와 복구만 허용한다. 프론트엔드가 learner_id를 지정하거나 JSON을 직접 초기 등록하지 않는다.

## 새 DB와 기존 DB

새 설치는 사용자 데이터 폴더의 임시 DB에서 구조 버전 1과 초기 등록을 완료한다. 연결을 모두 닫고 무결성을 확인한 뒤 최종 study.db가 없을 때만 이름을 바꾸고 정상 작업 큐를 연다. 실패한 임시 DB를 정상 DB로 선택하지 않는다.

기존 DB는 app_metadata의 앱 식별·구조 버전·등록 표시를 검사한다. 손상·읽기 실패·알 수 없는 구조를 새 설치로 바꾸지 않는다. 등록 표시가 없는데 기존 프로필·자료·시험이 있으면 불일치로 안내하고 덮어쓰지 않는다. 등록이 완료된 DB에서는 초기 자료를 매번 읽지 않는다.

## 화면 상태

React는 loading·ready·error를 구분하고 취소된 요청 결과를 반영하지 않는다. get_app_status는 초기화 성공 후 ready를 반환하며 실패 시 구조화된 오류를 반환한다. 현재 화면은 재시도를 제공하고 창 종료가 가능하다. 복구 기능은 이후 단계다.

브라우저 미리보기는 DB를 열지 않으며 Tauri 기능 대신 실제 저장이 없는 시제품임을 표시한다. 창 종료와 제출 전 최신 저장은 [응답 저장과 재개](06_응답저장과재개.md), 복구는 [자료 교환과 복구](08_자료교환과복구.md)를 따른다.
