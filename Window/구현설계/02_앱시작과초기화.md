# 앱 시작과 초기화

상태: 구현 기준. 로그인 단계 없이 준비가 끝나면 자료 선택 화면을 연다.

## 시작 순서

| 순서 | 담당과 입력 | 처리와 출력 |
| --- | --- | --- |
| 1 | `App.OnStartup` → `AppBootstrapper` | `Global\StudyApp.<사용자 SID>` named mutex로 해당 사용자의 한 실행만 허용. 이미 실행 중이면 새 프로세스를 종료하고 기존 앱 사용 안내 |
| 2 | `AppPaths` | `AppContext.BaseDirectory`에서 패키지 루트, `LocalApplicationData`에서 `StudyApp/study.db`와 `backups` 경로 결정 |
| 3 | `DatabaseInitializer` | DB 존재·식별·구조 버전 확인. 새 DB 생성 또는 지원하는 이전 버전의 백업·구조 변경 수행 |
| 4 | `InitialDataService.EnsureInstalledAsync` | 알려진 구조에서 초기 반영 표시를 확인하고, 필요한 경우 두 자료와 로컬 프로필을 한 트랜잭션으로 등록 |
| 5 | `AppBootstrapper` | 보존된 프로필 ID로 `LocalStudyContext` 생성. 서비스에는 이 ID를 주입하고 화면에서 사용자 ID를 받지 않음 |
| 6 | `SetupViewModel.LoadAsync` → `DatasetService` | DB의 자료 목록을 조회해 첫 화면 표시. 기존 미완료 시험은 기록 화면에서 선택해 재개 |

등록된 DB에서는 4단계가 초기 JSON을 다시 읽지 않는다. 첫 화면도 JSON 대신 DB 조회 결과를 사용한다.

## 새 DB와 기존 DB 구분

새 설치는 같은 앱 데이터 폴더의 새 임시 DB에 구조 버전 `1`을 생성하고 자료 등록까지 마친다. 초기화 중에는 그 임시 DB에 작업 큐를 연결한다. 모든 연결을 닫고 무결성을 확인한 뒤, 최종 경로가 여전히 없을 때 `study.db`로 이름을 바꾼다. 이후 최종 경로로 정상 작업 큐를 연다.

초기화 실패 시 최종 DB를 만들지 않고 오류와 재시도를 제공한다. 다음 실행은 최종 DB가 없으면 새 설치를 다시 시도한다. 실패한 임시 파일은 사용자 DB로 선택하지 않으며, 정리는 앱이 생성한 임시 경로만 대상으로 한다.

기존 DB는 `app_metadata`의 앱 식별값 `StudyApp`, DB 구조 버전과 초기 반영 표시를 검사한다. 식별·읽기 실패나 알 수 없는 구조는 오류로 처리한다. 기존 DB를 새 빈 DB로 덮어쓰지 않는다. 정상 구조에 초기 반영 표시가 없는 경우에만 동일한 초기 등록 절차를 수행한다.

## 실패와 종료

폴더 접근 실패·자료 오류·DB 오류를 구분해 초기화 화면에서 재시도와 종료를 제공한다. MainWindow의 학습 화면은 초기화 성공 전 활성화하지 않는다. 새 DB 전환에 실패하면 임시 결과를 성공으로 안내하지 않는다.

기존 DB 구조 변경은 [자료 교환과 복구](08_자료교환과복구.md)의 백업·복구 경계를 따른다. 종료 시에는 [응답 저장과 재개](06_응답저장과재개.md)의 저장을 기다린 뒤 작업 큐와 mutex를 해제한다.
