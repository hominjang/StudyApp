# 화면과 서비스 및 오류 처리 연결

상태: 구현 기준. 기존 [화면 흐름](../화면흐름/README.md)의 동작을 ViewModel과 서비스에 배치한다.

| ViewModel | 주요 서비스 호출 | 성공 후 동작 |
| --- | --- | --- |
| `SetupViewModel` | DatasetService.List/PreviewCandidates, ExamService.Start | 초기 저장 후 Exam 화면 |
| `ExamViewModel` | ExamQueryService.Resume, ExamService.SaveProgress | 한 문항 표시와 저장 상태 갱신 |
| `SubmissionViewModel` | ExamService.Submit/Complete | 제출 후 처리 화면, 완료 후 Results |
| `ResultsViewModel` | ExamQueryService.GetResult | 결과·현재 학습 상태 표시, 새 시험 설정으로 이동 |
| `HistoryViewModel` | ExamQueryService.ListHistory/Resume | 상태에 따라 Exam·제출 처리·Results로 이동 |
| `TransferViewModel` | TransferService.PreviewImport/ApplyImport/Export | 자료 목록 다시 조회 |
| 시작·복구 화면 | AppBootstrapper, BackupManager | 초기화 또는 복구 성공 후 Setup |

표의 호출명은 `Async`를 생략했다. NavigationService는 화면 생성과 전환을 담당하며 학습 규칙이나 SQL을 포함하지 않는다. DialogService는 파일·폴더 선택과 미응답·복구 확인을 담당한다.

## 화면 상태와 반환 계약

서비스의 공개 반환은 `OperationResult<T>`로 성공 DTO 또는 오류 정보를 전달한다. 오류는 code·한국어 message·필요 시 항목 경로·재시도 가능 여부를 포함한다. 예측 가능한 입력 오류도 저장 변경 후에는 정상 반환으로 삼키지 않는다. 트랜잭션 안의 거부는 내부 예외로 ROLLBACK한 뒤 서비스 경계에서 오류 결과로 변환한다.

| 오류 코드 | 화면의 대응 |
| --- | --- |
| `ValidationError`, `UnsupportedFormat` | 파일·필드 또는 설정 항목을 표시하고 수정 후 재시도 |
| `NoCandidates`, `InvalidCount` | 자료 선택에 남아 모드·범위·문제 수 수정 |
| `NotFound`, `OwnershipMismatch`, `DataInconsistent` | 해당 기록을 임의 재생성하지 않고 오류 표시 |
| `RevisionConflict`, `ImportChanged` | 입력을 보존하고 저장 상태 또는 가져오기 미리보기를 다시 확인 |
| `StorageBusy`, `StorageFailure` | 저장 완료를 표시하지 않고 같은 요청으로 재시도 |
| `StateUnknown` | 같은 ID의 상태를 확인한 뒤 화면 경로 결정 |
| `UnsupportedDbVersion`, `RecoveryRequired` | 학습 화면 진입을 막고 호환 버전 또는 복구 경로 안내 |

ViewModel은 idle·loading·saving·processing·error 상태와 최신 요청 번호를 관리한다. AsyncCommand는 처리 중 같은 명령의 중복 실행을 막는다. 다른 화면으로 전환한 뒤 도착한 응답은 시험 ID와 화면 실행 세대가 맞을 때만 반영한다.

저장 중에도 입력을 받을 수 있지만 최종 제출과 종료 전에는 최신 값을 확정한다. 자동 저장 실패는 화면 입력을 지우지 않으며, 버튼의 사용 가능 상태만으로 저장 성공을 판단하지 않는다.

## 표시와 로그

작성 DTO에는 정답·허용 표기·해설을 넣지 않고 결과 DTO는 completed일 때만 제공한다. 내부 저장 모델을 그대로 바인딩하지 않는다.

로그에는 오류 코드·작업 종류·시험 ID와 예외 원인을 남기고 입력 답변·정답 전문은 기본 기록하지 않는다. 초기 등록이나 자료 검증 오류는 파일과 문항 ID·필드 경로로 찾을 수 있게 한다. 사용자 메시지는 SQL과 stack trace 대신 취할 수 있는 동작을 설명한다.
