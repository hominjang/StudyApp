# 웹 화면과 Rust 명령 및 오류 처리

목록 DTO는 `kind=exam`의 정상 행과 `kind=error`의 오류 행으로 구분한다. 오류 행에는 `row_key`와 안내만 있고 열기 버튼·추정 시각/점수/문항 수는 표시하지 않는다. DB 2 평가·오답노트 명령은 MixedResultWorkspace의 버튼까지 연결했다. 기존 DB 1 결과와 DB 2의 네 평가 개수·평가 대기를 구분한다. [명령 계약](확장/02_명령과화면연결.md)·[검증 결과](../작업계획/16_손상기록과평가명령.md)

상태: 앱 상태·자료 목록·자료 학습·세 출제 모드·후보 수·전체 기록·자동 저장·재개·제출·결과와 자료 가져오기/갱신 명령 구현. 내보내기·백업·복구는 후속 단계다.

| React 기능 | Rust 명령 | 성공 후 동작 |
| --- | --- | --- |
| 앱 상태 | get_app_status | 준비·오류 상태 반영 |
| 자료 목록 (구현) | list_datasets | ID·제목·순서·활성 문항 수·현재 프로필 오답 대상 수만 반환 |
| 자료 학습 (구현) | browse_study_materials | 현재 활성 질문·정답/참고 기준·선택 해설을 페이지 단위로 읽음. 시험/학습 상태 쓰기 없음 |
| 자료 편집 (구현) | update_study_material | 묶음 revision 검사 후 정답/허용 표기·참고 기준·해설만 변경. 과거 시험과 학습 상태 보존 |
| 출제 후보 수 (구현) | preview_candidates | 선택 범위와 현재 오답 상태로 후보 수 반환 |
| 시험 시작 (세 모드 구현) | start_exam | 일반·오답 우선·오답만 선택 후 시험과 스냅샷 저장 |
| 시험 상태 (구현) | get_exam_session | 소유자·개수·위치를 검사하고 정답 없는 DTO 반환 |
| 답변 자동 저장 (구현) | save_progress | revision·전체 답변·위치를 저장하고 saved·already_saved·stale·locked 구분 |
| 제출과 처리 (구현) | submit_exam, complete_exam | 확정 후 결과 조회 |
| 결과 (구현) | get_exam_result | 완료 시험만 정답 스냅샷과 현재 학습 상태 반환 |
| 미완료 목록과 재개 (구현) | list_pending_exams, get_exam_session | 저장된 스냅샷으로 작성·처리 중 분기. 목록은 질문·정답·답변을 포함하지 않음 |
| 전체 기록 (구현) | list_exam_history | 전체·진행 중·처리 중·완료 필터, 완료 순번 정렬과 상태별 열기 |
| 자료 가져오기 (구현) | preview_import, apply_import | 파일 검증·미리보기 토큰·revision 확인 후 자료 목록 갱신 |
| 가져올 파일 선택 (구현) | choose_import_file | Windows 대화상자에서 선택한 파일만 UTF-8·크기 검사 후 파일명/내용 반환. 취소는 null |
| 자료 내보내기 (미구현) | export_dataset | 후속 구현 |
| 복구 | create_backup, restore_backup | 초기화 경로 다시 수행 |

모든 invoke는 src/bridge에서 감싸고 화면 컴포넌트가 SQL·파일 경로를 조합하지 않는다. 가져오기는 Rust의 Windows 대화상자에서 고른 파일만 읽는다. 프런트엔드가 임의 경로를 넘기는 읽기 명령이나 광범위한 파일 권한을 추가하지 않았다. frontend public에 실제 자료를 넣지 않는다.

## 반환과 오류

Rust 명령은 성공 DTO 또는 직렬화 가능한 오류를 반환한다. 오류의 필드는 code·message·필요 시 field_path·retryable이다. 입력 오류도 변경이 시작된 트랜잭션 안에서는 rollback한 뒤 반환한다.

| 코드 | 화면 대응 |
| --- | --- |
| ValidationError, UnsupportedFormat | 설정 또는 파일의 해당 항목 수정 |
| NoCandidates, InvalidCount | 출제 설정에서 범위·문제 수 변경 |
| NotFound, OwnershipMismatch, DataInconsistent | 기록을 재생성하지 않고 오류 안내 |
| RevisionConflict, ImportConflict | 입력 유지 후 최신 상태 재확인. 가져오기는 미리보기를 다시 생성 |
| StorageBusy, StorageFailure | 저장 성공으로 표시하지 않고 같은 요청 재시도 |
| StateUnknown | 같은 ID로 상태 조회 후 작성·처리·결과 분기 |
| UnsupportedDbVersion, RecoveryRequired | 초기화·복구 화면 제공 |

list_exam_history와 list_pending_exams는 한 시험을 읽지 못해도 목록 전체를 실패시키지 않는다. 해당 행에만 `error` 안내를 담고 열기 버튼 없이 표시하며, 그 기록은 지우거나 새 시험으로 대체하지 않는다. 학습 시작 화면은 자료 목록과 미완료 목록을 따로 처리해, 미완료 목록 조회가 실패해도 자료 선택과 새 시험 시작을 막지 않는다.

React 상태는 기능별 hook·reducer로 분리하고 loading·saving·processing·error와 최신 요청 번호를 관리한다. 연속 요청의 과거 응답은 적용하지 않으며 버튼 중복 입력을 막는다. 단순 useEffect 재실행이나 재렌더로 시험을 생성하지 않는다.

## 입력과 표시

시험 작성 DTO에는 정답·허용 표기·해설을 넣지 않고 완료 결과 DTO에만 포함한다. 별도 [자료 학습](../화면흐름/08_자료학습.md)은 현재 자료를 공개하는 읽기 전용 DTO를 사용한다. 입력은 controlled state 원문을 유지하고 composition 이벤트를 고려한다. 새 단답형은 한 줄 입력, 줄바꿈 있는 기존 답변은 [복원용 여러 줄 입력](../작업계획/13_기존답변복원보완.md)으로 표시하며, Enter로 시험을 제출하지 않는다. 기록에서 이어 풀기/결과 보기와 자료 학습은 시험 설정을 바꾸지 않는다. 결과의 "같은 설정으로 다시 준비"와 "오답 대상 복습"에서만 설정을 채운다.

로그와 검증 결과에는 실제 문항·정답·응답 전문을 넣지 않는다. 사용자 메시지는 SQL 오류 대신 가능한 재시도를 설명한다. 브라우저 미리보기는 저장 기능이 없음을 구분하며 실제 앱의 조회 결과로 위장하지 않는다.
