# 답변 입력과 자동 저장 및 재개

신규 DB 2의 서술형은 빈 답변부터 여러 줄 입력을 사용하며 같은 자동 저장/revision/제출 잠금을 유지한다. 단답형의 기존 여러 줄 원문 복원도 유지한다. [DB 2 입력과 저장](확장/04_시험저장소와결과화면.md)

상태: save_progress·미완료 시험 목록·이어 풀기·제출 처리 재개와 정상 창 닫기 구현. 저장 규칙은 [진행 저장과 복구](../저장방식/04_진행상태저장과복구.md)를 따른다.

## 화면의 편집 상태

React의 useExamProgress가 시험 ID·원문 답변 배열·현재 위치·편집 revision을 유지하고 AutosaveCoordinator가 persistedRevision과 저장 상태를 관리한다. 복원한 revision에서 시작해 답변 또는 위치가 바뀔 때 1씩 늘린다. 화면 번호는 저장 position에 1을 더해 표시한다.

입력 컴포넌트는 원문을 controlled state로 보존한다. 새 단답형과 줄바꿈 없는 답변은 한 줄 input으로 받는다. 이전에 저장한 CR/LF 답변은 AnswerInput의 textarea로 복원하고 표시와 저장 원문을 분리한다. answerText는 편집 구간만 교체해 바꾸지 않은 CR·CRLF를 유지하며, 무수정 입력은 원문을 그대로 저장·제출한다. 줄바꿈을 지워도 편집 중 컴포넌트 종류를 바꾸지 않는다.

한 줄 입력에서 Enter·붙여 넣기의 기존 동작은 유지하고, 복원용 여러 줄 입력의 편집은 사용자 입력으로 보존한다. Enter로 시험을 제출하거나 다음 문항으로 이동하지 않는다. 기존 답변 복원 보완은 서술형 지원과 별개다. [구현·검증 결과](../작업계획/13_기존답변복원보완.md)

`AutosaveCoordinator`는 500ms의 입력 대기 타이머와 마지막 요청 기준 2초 제한을 관리한다. 같은 시험에서 저장 하나를 실행 중이면 최신 미전송 스냅샷 하나를 보관한다. 각 요청은 가변 배열을 참조하지 않는 전체 답변·위치의 복사본이다.

## 진행 저장 계약과 실행

`save_progress`의 입력은 시험 ID·revision·답변 배열·현재 위치다. 반환은 outcome(`saved`·`already_saved`·`stale`·`locked`)과 revision·status이거나 구조화된 오류다. stale·locked 응답으로 현재 입력이 저장됐다고 표시하지 않는다.

쓰기 트랜잭션 안에서 다음을 수행한다.

1. 시험의 프로필과 상태를 확인한다. submitted/completed면 변경 없이 Locked를 반환한다.
2. 위치와 답변 수를 검사한다. 저장된 문항 키와 순서는 변경하지 않는다.
3. 낮은 revision은 변경 없이 Stale, 같은 revision·같은 내용은 AlreadySaved, 같은 revision·다른 내용은 충돌로 처리한다.
4. 높은 revision이면 모든 답변 원문·현재 위치·revision·saved_at을 함께 저장한다.

COMMIT 후 해당 시험과 화면 실행 세대가 여전히 같을 때만 완료 알림을 적용한다. `persistedRevision`은 성공한 버전까지 올리고, editRevision과 같아야 저장 완료로 표시한다. Stale 알림만으로 최신 입력을 저장 완료로 표시하지 않는다.

## 문항 이동과 종료

번호 이동은 현재 input 값을 반영하고 새 위치까지 포함한 저장을 즉시 요청한다. 다른 문항으로 이동해도 메모리의 전체 답변은 유지한다. 실패 시 이동한 화면에서 미저장 표시와 재시도를 제공한다.

저장 후 나가기와 창 닫기는 타이머를 멈추고 현재 입력을 반영한 뒤, 진행 중 요청과 최신 저장의 완료를 기다린다. 저장 성공 후에만 화면 전환 또는 프로세스 종료를 계속한다. 실패하면 입력을 유지하고 재시도 또는 현재 화면에 남기를 제공한다. 강제 종료 후에는 마지막 COMMIT까지 복원하며 미저장 입력이 보존됐다고 안내하지 않는다.

창 닫기는 App의 watchCloseRequest와 시험 화면의 prepareToLeave를 연결한다. 종료 전 저장 준비가 끝나기 전에는 시험 시작·재개를 차단한다. Tauri main 창에 destroy 권한을 부여하고, 저장 확인 후에만 창을 파괴한다.

## 재개와 최종 제출 전환

`ResumeAsync(examId)`는 저장된 스냅샷만 읽는다. in_progress면 답변과 위치 및 revision으로 시험 상태를 다시 만들고 자동 저장을 시작한다. submitted면 입력 없는 처리 화면에서 `CompleteAsync`를 재시도한다. completed면 결과 화면을 연다. 현재 원본으로 다시 출제하거나 채점 기준을 바꾸지 않는다.

최종 제출은 확인 화면을 거친 뒤 타이머·신규 편집을 일시 정지하고, 남은 저장과 최신 상태를 정리한다. `SubmitAsync`가 최종 답변 저장과 상태 전환을 한 번에 처리하므로 단순 autosave 성공만으로 제출됐다고 표시하지 않는다. 제출 실패와 확인 불가 상태의 복구는 [제출과 결과](07_제출채점과결과.md)를 따른다.

미완료 목록은 list_pending_exams, 복원은 get_exam_session을 사용하며 제출 상태는 complete_exam으로 처리한다. 완료 기록 목록은 5단계에서 연결했다. 검증은 [자동 저장과 재개 결과](../작업계획/09_자동저장과시험재개.md), [기록 조회 결과](../작업계획/10_기록조회와오답재학습.md), [기존 답변 복원 보완](../작업계획/13_기존답변복원보완.md)을 따른다.
