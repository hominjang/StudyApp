# 빌드와 배포 및 구현 검증

상태: 구현 기준. 아래 명령은 프로젝트 생성과 SDK 준비 후 실행할 절차이며 아직 실행하지 않았다.

## 빌드 구성

SDK와 패키지 버전을 고정한 뒤 저장소 루트에서 restore·build·test를 수행한다. Core는 화면 없는 규칙 검증, Infrastructure는 임시 파일 DB와 JSON을 사용하는 통합 검증을 담당한다. 테스트 프레임워크와 runner의 정확한 패키지 버전은 첫 프로젝트 생성 시 복원 호환성을 확인해 기록한다.

```powershell
dotnet restore Window/StudyApp.sln --locked-mode
dotnet build Window/StudyApp.sln -c Release --no-restore
dotnet test Window/StudyApp.sln -c Release --no-build
dotnet publish Window/src/StudyApp.Desktop/StudyApp.Desktop.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=false -p:PublishTrimmed=false -o Window/artifacts/publish/win-x64
```

최초 restore에서는 잠금 파일을 생성한 다음 이후 복원에 locked-mode를 사용한다. 실제 SDK·RID별 복원과 publish 성공을 확인하고 빌드 기록에 남긴다.

self-contained 배포 폴더에 런타임과 앱 의존성 및 `Assets/InitialData`를 포함한다. DLL과 자료 경로를 폴더 구조로 유지하며 초기에는 단일 파일과 trimming을 사용하지 않는다. 배포 방식의 근거는 [공식 .NET 배포 문서](https://learn.microsoft.com/en-us/dotnet/core/deploying/)다.

## 단계별 실제 코드 검증

| 검증 영역 | 확인할 결과 |
| --- | --- |
| 프로젝트·시작점 | WPF 창 실행, 초기화 중 화면 차단, 단일 실행, 준비 오류 후 재시도 |
| 초기 자료 | 실제 두 자료 254문항·ID·순서 보존, 재실행 미중복, 설치 중 오류 전체 롤백 |
| DB 스키마 | 외래 키 활성화, 중복 위치·문항과 잘못된 상태 거부, 실제 서비스의 여러 행 상태 조건 |
| 채점과 출제 | 기존 1,705건 채점 예시, 공백·case·Unicode 차이, 모드별 후보와 선택·표시 순서 |
| 시험 저장 | 생성 실패·같은 ID 재시도, 오래된 revision과 동일 버전 충돌, 미저장 표시 |
| 제출과 완료 | 입력 잠금, 제출 재개, COMMIT 전 오류 전체 롤백, 반복 요청의 횟수 미증가 |
| 오답 상태 | 3회 연속 정답 해제, 중간 오답 초기화, 미출제 시험 제외, 완료 순번과 시계 역행 |
| 원본 변경 | 스냅샷 불변, 누락 문항 비활성화와 재등록 연결, 과거 판정과 현재 상태 구분 |
| 자료 교환 | 미지원·불일치 자료 거부, 미리보기 후 변경 충돌, 외부 파일 변경, 출력 실패·기존 폴더 보존 |
| 백업과 복구 | 임시 파일 DB 백업·복구, 구조 변경 오류 롤백, 알려지지 않은 DB 버전 차단 |

기존 [설계 검증 모델](../작업계획/검증/README.md)은 참고 시나리오다. 실제 C# 서비스와 저장소의 테스트 결과를 별도로 남기며 모델 테스트의 통과를 실제 구현 통과로 계산하지 않는다.

## 화면과 배포 확인

실제 WPF 화면에서 한글 조합·번호 이동·미응답 확인·저장 오류·정상 종료를 검증한다. 별도 실행 프로세스의 중단 전후로 마지막 저장 상태와 제출 후 처리 재개도 확인한다. SQLite 장애 주입·프로세스 중단 검증과 실제 디스크 고장·강제 전원 종료는 검증 범위를 구분해 기록한다.

초기 배포물은 버전별 ZIP과 압축을 풀어 실행하는 안내다. 새 버전은 새 앱 폴더에 풀고 기존 프로세스를 종료한 뒤 실행한다. 업데이트로 `%LOCALAPPDATA%/StudyApp`을 제거하지 않으며 필요한 구조 변경은 앱의 백업·migration을 거친다. 자동 업데이트 서버와 설치 프로그램은 초기 산출물에 포함하지 않는다.

개발 SDK와 .NET 런타임이 없는 대상 Windows x64 환경에서도 실행·자료 복사·첫 시험·종료 후 재개·기존 DB 업데이트를 확인한다. 추가 아키텍처와 Windows 버전은 실제 확인한 범위만 지원 범위에 기록한다. 실행 검증 전 지원한다고 단정하지 않는다.

실제 자료를 포함하는 패키지와 자료 기반 검증은 로컬 data를 준비한 환경에서만 수행한다. 새 clone에 자료가 없으면 해당 검증을 통과로 표시하지 않는다. 복사된 자산과 Window/artifacts의 배포물은 Git에서 제외한다. [실제 데이터 관리 원칙](<../../공통 개발 문서/개발원칙/01_실제데이터와Git관리.md>)을 따른다.
