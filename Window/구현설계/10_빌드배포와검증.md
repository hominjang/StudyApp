# 웹 UI와 Windows 앱의 빌드 및 검증

상태: Windows x64 release exe와 초기 자료를 담은 실행 폴더 생성 지원. 설치 패키지와 다양한 배포 환경 검증은 이후 단계다.

## 웹 UI 실행

프로젝트의 Node 24 버전을 사용해 Window에서 실행한다. 로컬 .tools 환경을 쓸 때는 해당 Node 폴더를 현재 프로세스 PATH 앞에 추가한다. npm cache도 .tools 아래로 지정한다.

```powershell
cd Window
npm ci
npm run dev
npm run build
```

Vite 개발 주소는 http://127.0.0.1:1420 이다. 이 주소는 개발용이며 배포용 서버를 운영하는 구성이 아니다. 웹 빌드는 TypeScript 검사와 정적 번들을 생성한다. package-lock.json은 Git에 포함하고 node_modules·dist·.tools는 제외한다.

현재 PC의 프로젝트 전용 Node 선택과 실행은 루트에서 `& ./Window/scripts/run-web.ps1 -Task dev` 또는 `-Task build`로 수행할 수 있다. 전환 과정의 실제 결과는 [웹 UI 전환 기록](../작업계획/06_웹UI전환.md)을 참고한다.

## Windows 실행과 배포

공식 [Windows 선행 조건](https://v2.tauri.app/start/prerequisites/)의 Rust MSVC 도구 체인·Microsoft C++ Build Tools·WebView2를 확인한 뒤 실행한다.

```powershell
cd Window
npm run tauri:dev
cargo test --manifest-path src-tauri/Cargo.toml
npm run tauri:build
```

현재 bundle은 비활성화되어 있다. 설치 없이 실행할 폴더는 루트의 `& ./Window/scripts/run-web.ps1 -Task package:exe`로 만든다. 원본 자료 유무·경로를 먼저 확인하고 Tauri release 빌드 후 실행 파일과 catalog에 지정된 초기 자료만 Git 제외된 Window/artifacts의 새 폴더에 복사한다. 매번 다른 폴더를 사용해 기존 산출물을 덮어쓰지 않는다. 해시 목록과 실행 안내도 함께 생성한다. exe 실행에는 Node·Rust·개발 서버가 필요하지 않으며 WebView2 Runtime이 필요하다. [실행 파일 결과와 안내](../작업계획/11_Windows실행파일.md)

개발 실행은 루트에서 `& ./Window/scripts/run-web.ps1 -Task tauri:dev`를 사용한다. installer·서명·WebView2 설치와 업데이트 검증은 7단계에 남아 있다.

## 자료와 검증 범위

실제 data를 frontend src·public에 넣지 않는다. 초기 자료는 개발용 resources/initial-data와 exe 옆 initial-data에 별도로 배치한다. 원문·문제집·채점 예시·기존 DB는 실행 폴더에 넣지 않는다. resources/initial-data와 target·artifacts는 모두 Git에서 제외한다. release 앱의 DB는 %LOCALAPPDATA%/StudyApp/study.db이며 개발용 .tools/runtime DB를 자동 이전하지 않는다.

| 검증 | 기준 |
| --- | --- |
| 웹 화면 | 설정 선택·입력·화면 이동, 반응형 배치와 키보드 포커스 |
| Rust 연결 | invoke 성공·오류 DTO·준비 전 명령 거부 |
| SQLite | 실제 임시 DB의 초기 등록·관계 제약·상태 전환과 롤백 |
| 학습 규칙 | 실제 코드에서 채점 예시와 모드별 출제·3회 연속 집계 |
| 저장·재개 | 오래된 요청, 제출 잠금, 종료 전 저장, 처리 중단과 같은 ID 재시도 |
| 자료·백업 | 갱신 충돌·스냅샷 보존·출력 오류·정상 백업 복구 |
| Windows 배포 | WebView2·DPI·IME·창 종료와 설치·업데이트 후 기록 유지 |

기존 [Python 설계 모델](../작업계획/검증/README.md)의 결과는 Rust·React 앱 검증과 별도다. 브라우저 화면이 열리거나 웹 빌드가 성공한 것으로 SQLite·실제 시험·네이티브 실행까지 완료 처리하지 않는다.
