# 학습 데이터 저장과 갱신

상태: 초기 구현 기준. 필드는 [학습 데이터](<../../공통 개발 문서/상세설계/데이터/01_학습데이터.md>)와 [보충 정보](<../../공통 개발 문서/상세설계/데이터/01_1_보충정보.md>)를 따른다.

| 논리 테이블 | 식별과 내용 |
| --- | --- |
| `datasets` | 묶음 ID, 이름, 현재 자료 내용의 해시 |
| `items` | 묶음·문항 ID의 복합 키, 질문과 정답 및 허용 표기, 기본 순서와 활성 여부 |
| `supplements` | 묶음·문항 ID의 복합 키와 선택적인 해설 및 출처 등 |
| `app_metadata` | DB 구조 버전과 초기 자료 반영 여부 |

문항은 묶음, 보충 정보는 문항에 연결한다. 필수 값과 복합 키를 검증하고 원본 파일명이나 질문 문장으로 ID를 대체하지 않는다.

## 최초 실행

1. 초기 목록의 Android 107문항과 일반 CS 147문항 및 보충 정보를 읽어 검증한다.
2. 프로필과 자료 및 초기화 완료 표시를 한 트랜잭션으로 저장한다.
3. 초기화가 실패하면 전체를 되돌리고 오류와 재시도를 제공한다.

이후 실행에서는 DB 자료를 사용한다. 패키지의 초기 파일을 매번 가져와 기존 자료와 기록을 덮어쓰지 않는다. 앱 업데이트로 제공 자료가 달라져도 갱신은 명시적인 자료 갱신 절차로 적용한다.

## 조회와 갱신

현재 활성 문항만 새 출제 후보로 조회하고, 순서는 선택한 묶음 순서와 저장된 문항 순서를 따른다. 실제 문항 수를 조회해 목록에 표시한다.

같은 묶음을 전체 갱신할 때는 입력을 모두 검증한 뒤 변경을 한 번에 저장한다. 빠진 기존 문항은 비활성 상태로 보관하고 ID를 재사용하지 않는다. 보충 파일을 생략하면 기존 보충 정보를 유지한다. 기존 보충 항목은 새 입력의 같은 문항 항목이 있을 때만 해당 항목 전체로 교체한다.

외부 JSON 파일의 수정이나 삭제만으로 가져온 DB 자료가 바뀌지는 않는다. 자료 갱신은 이후 새 시험에만 적용하고, 진행 중 시험과 완료 기록은 당시의 보존 내용을 사용한다.

변경의 의미에 따른 ID 기준은 [변경과 재가져오기](<../../공통 개발 문서/상세설계/데이터/03_1_변경과재가져오기.md>)를 따른다.

## 자료 학습에서 편집

2026-11-27부터 현재 정답/허용 표기 또는 참고 답안/핵심 내용·해설을 앱에서 수정할 수 있다. DB 1/2의 활성 문항과 묶음 revision을 확인한 쓰기 트랜잭션으로 대상 내용·해시·revision만 함께 변경한다. 기존 시험 스냅샷·응답·판정·오답/연속 정답은 유지하며 원본 JSON은 자동 수정하지 않는다. 충돌·재시도·보충 필드 보존은 [자료 학습 편집](../구현설계/11_자료학습편집.md)을 따른다.
