# 시험 완료 처리와 중복 반영 방지

상태: 초기 구현 기준. 저장과 학습 집계가 함께 성공하도록 처리한다.

## 제출 확정

최신 답변과 위치를 저장하고 `in_progress`에서 `submitted`로 변경하는 작업을 한 트랜잭션으로 처리한다. 실패하면 기존 진행 상태를 유지하고, 성공한 뒤에만 입력을 잠근다.

채점은 보존한 정답과 허용 표기로 계산한다. 계산 실패 시 제출된 답변은 보존하고 완료로 바꾸지 않는다.

## 완료 트랜잭션

1. 쓰기 트랜잭션을 시작하고 시험 상태를 다시 확인한다. 이미 완료되었으면 기존 결과를 반환한다.
2. 제출된 시험의 전체 문항 판정을 검사하고 응답에 저장한다.
3. 같은 사용자의 다음 `completion_order`를 부여하고 완료 시각을 기록한다. 이 값은 이후 재시도에서 바꾸지 않는다.
4. 해당 문항들의 완료 기록을 완료 순번으로 읽어 오답 대상과 연속 정답 수를 다시 계산한다.
5. 시험을 `completed`로 확정한 상태와 판정 및 학습 상태를 COMMIT한다.

3단계에서 현재 시험의 상태를 같은 트랜잭션 안에서 완료로 바꿔 4단계의 계산에 포함한다. 외부 조회에는 COMMIT 후에만 완료 상태가 보인다. 도중 실패하면 이번 트랜잭션의 변경 전체를 되돌린다.

## 중복과 순서

사용자·완료 순번은 유일해야 한다. 완료 순번은 트랜잭션 안에서 부여하므로 시스템 시계가 바뀌어도 학습 결과의 적용 순서는 유지한다.

학습 상태는 완료된 원본 결과에서 재계산한다. 같은 시험의 처리 재시도나 결과 재조회가 과거 결과를 추가하지 않는다. 정답 횟수를 무조건 더하는 방식으로 재시도를 처리하지 않는다.

쓰기 전 상태 확인을 같은 트랜잭션에서 수행하고, 잠금 실패 시 재시도를 안내한다. 처리 경계는 [SQLite 트랜잭션 제어](https://www.sqlite.org/lang_transaction.html)를 따른다.
