# 학습 앱 저장 구성

상태: 초기 자료 등록·자료 조회·단일 로컬 프로필의 SQLite 저장 구현. 시험 기록·백업·자료 교환은 이후 단계다.

자료 교환은 JSON, 실행 중 자료와 사용자 기록의 보관은 로컬 SQLite로 나눈다. 관련 기록을 함께 확정하기 위해 트랜잭션을 제공하는 저장소를 선택했다. [SQLite 트랜잭션 문서](https://www.sqlite.org/transactional.html)

| 구분 | 위치와 역할 |
| --- | --- |
| 제공하는 초기 자료 | 패키지에 포함한 [두 묶음 목록](../../data/initial/catalog.json)과 JSON 파일 |
| 실행 중 자료와 기록 | Windows 사용자별 앱 데이터 폴더의 `StudyApp/study.db` |
| DB 백업 | 같은 사용자 데이터 폴더의 `StudyApp/backups/` |
| 가져오기와 내보내기 | 사용자가 지정한 JSON 파일. 실행 중 DB와 별도 |

초기 버전은 한 PC의 로컬 학습 프로필 하나를 사용한다. 최초 초기화 때 생성한 `learner_id`를 이후 실행에서도 유지한다. 별도 로그인 없이 실행하며, 기기 간 자동 동기화는 이번 구현 범위에 포함하지 않는다.

## 저장 공통 기준

- 쓰기는 하나의 처리 큐에서 실행하고 작업마다 짧은 트랜잭션을 사용한다.
- 연결마다 `foreign_keys=ON`, `synchronous=FULL`, `busy_timeout=3000`을 적용하고 설정값을 확인한다. 잠금이나 디스크 오류는 성공으로 처리하지 않는다.
- 저장 완료는 COMMIT 성공을 기준으로 표시한다. 메모리 변경만으로 저장 성공을 알리지 않는다.
- 문자열은 공백·대소문자·문장부호와 입력 원문을 보존한다. 채점은 앱의 완전 일치 비교로 수행한다.
- 시각은 UTC와 시간대가 명시된 형태로 저장하고 화면에서 사용자 시간대로 표시한다. 학습 결과 반영 순서는 별도 완료 순번을 사용한다.

외래 키의 연결별 활성화와 동기화 설정은 [외래 키 문서](https://www.sqlite.org/foreignkeys.html), [PRAGMA 문서](https://www.sqlite.org/pragma.html#pragma_synchronous)를 근거로 한다.

JSON 형식 버전과 DB 구조 버전은 별도로 관리한다. 앱이 만드는 learner_id·exam_id·복제 dataset_id는 소문자 하이픈 UUID v4로 생성한다. 가져온 dataset_id·item_id는 공통 ID 형식(ASCII 소문자·숫자, 단일 하이픈 구획, 1~64자)을 검증하고 유효한 값은 그대로 보존한다. 세부 항목은 [저장 문서 목차](README.md)를 따른다.
