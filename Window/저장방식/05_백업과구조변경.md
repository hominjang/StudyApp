# 사용자 DB 백업과 구조 변경

상태: 초기 구현 기준. 자료 교환과 사용자 DB 보존을 구분한다.

2026-11-26에 원본 읽기 전용의 `prepare_v2_copy`와 가상 전환 검증을 구현했다. 이것은 새 사본을 준비하는 API이며 활성 DB 교체·복구 화면과 앱 자동 전환은 아직 미구현이다. 아래는 그 기능까지 포함한 목표 기준이다. [구현 범위와 제한](../작업계획/15_확장파서와전환기반.md)

## 백업과 복구

DB 구조를 바꾸기 전에 읽을 수 있는 현재 DB의 백업을 별도 파일로 만든다. 실행 중 DB의 백업은 [SQLite Backup API](https://www.sqlite.org/backup.html)로 일관된 사본을 생성한다.

백업은 새 파일에 만들고 무결성 확인 후 정상 백업으로 등록한다. 생성 실패 시 구조 변경을 중단하고 기존 DB를 유지한다. 실행 중 DB 파일만 일반 파일 복사로 교체하지 않는다.

손상이나 읽기 실패가 나면 오류와 마지막 정상 백업 복구 경로를 안내한다. 자동으로 빈 DB를 만들어 기록이 사라진 것처럼 처리하지 않는다. 복구는 모든 쓰기를 중단하고 연결을 닫은 상태에서 사용자가 선택한 정상 백업으로 수행한다.

초기 버전의 기본 보존 대상은 구조 변경 직전의 정상 백업이다. 임의 시험 기록 삭제와 DB 초기화 기능은 제공하지 않는다.

## DB 구조 버전

DB 내부 메타데이터에 구조 버전을 저장한다. 지원하는 이전 버전은 백업 후 순차 변경하며, 변경과 버전 기록을 같은 트랜잭션으로 반영한다.

실패하면 변경을 되돌리고 원래 버전으로 남긴다. 앱보다 새로운 DB 버전은 쓰기를 막고 호환되는 앱이 필요함을 안내한다. 알 수 없는 버전을 기존 버전으로 추정해 열지 않는다.

백업 복구는 사용자·시험 ID와 완료 순번 및 보존된 정답 기준을 유지한다. 복구 후 파생 학습 상태는 완료된 기록에서 재계산해 확인한다. 실제 디스크 오류와 앱 업데이트 과정은 구현 단계에서 검증한다.
