# 학습 자료 가져오기와 내보내기

상태: 2026-11-27 가져오기·갱신 구현. 내보내기·독립 복제는 설계 단계다. [사용 안내](../사용안내/01_문제자료추가.md)·[검증 결과](../작업계획/18_배포앱자료추가.md)

가져오기 대상은 `learning.json`과 선택적인 같은 버전/묶음의 `supplement.json`이다. 기존 DB 1은 JSON `1.0`만, DB 2는 `1.0`/`2.0`을 지원한다. 원문·변환 보고서·사용자 응시 기록은 출제 자료로 가져오지 않는다. 미지원 버전은 명시적으로 안내하고 DB를 자동 전환하지 않는다.

## 가져오기

1. 파일을 작업 메모리로 읽어 필수 필드와 형식 버전 및 ID, 짧은 정답과 허용 표기를 검증한다.
2. 보충 파일이 있으면 같은 묶음인지 확인한다. 연결할 문항이 없는 보충 항목은 오류로 안내한다.
3. 새 자료인지 기존 자료의 갱신인지와 추가·변경·비활성화될 문항을 미리 표시한다.
4. 적용을 선택하면 해당 자료와 보충 정보 및 순서를 한 트랜잭션으로 저장한다. 오류 시 기존 자료 전체를 유지한다.

같은 ID와 내용이면 중복 생성하지 않는다. 같은 묶음의 갱신은 사용자 선택으로 적용한다. 갱신 파일은 앞으로 출제할 전체 목록이며 빠진 문항은 비활성화한다. 보충 정보 생략/교체는 사용 안내를 따른다. 기존 시험과 학습 기록은 원문과 별도로 보존한다. 별도 자료로 복제할 때 새 묶음 ID를 부여하는 기능은 후속 구현이다.

## 내보내기

선택한 자료의 활성 문항을 `learning.json`으로, 연결된 보충 정보를 `supplement.json`으로 출력한다. 각 파일은 UTF-8 JSON이고 문자열을 자동 정리하지 않는다. ID와 문항 순서 및 명시된 허용 표기를 유지한다.

대상 상위 폴더 안의 임시 폴더에 두 파일을 모두 완성하고 검증한 뒤, 존재하지 않는 새 출력 폴더명으로 이동하고 성공을 표시한다. 대상 이름이 이미 있으면 다른 이름을 안내한다. 실패하면 불완전한 출력을 성공으로 안내하거나 기존 사용자 파일을 자동 덮어쓰지 않는다.

원문 대응과 보고서 보관은 자료 준비 과정의 산출물이다. 사용자 응시 기록의 교환은 JSON 자료 내보내기와 섞지 않으며, DB 보존은 [백업과 구조 변경](05_백업과구조변경.md)을 따른다.

## 호환성

JSON `schema_version`과 DB 구조 버전은 다르다. 현재 공통 2.0 명세에 맞는 유형별 자료만 2.0 파서로 읽으며, 이전 파일럿의 버전 선언만 보고 호환된다고 판단하지 않는다. 서술형을 1.0으로 바꿔 단답형으로 읽지 않는다.
