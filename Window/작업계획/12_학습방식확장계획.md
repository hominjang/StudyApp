# Windows 기초 용어·서술형·사용자 평가 확장

작성일: 2026-11-26. 수정일: 2026-11-27. 상태: DB 2 시험 저장소·혼합 입력/평가·기초 복습 연결과 가상 Windows 검증 완료. 기존 사용자 DB 활성 전환·실제 자료 보강·새 배포 exe는 미적용. [결과](17_혼합시험과평가화면.md)

## 진행 순서

| 순서 | Windows 작업과 산출물 | 완료 확인 |
| --- | --- | --- |
| 확장 1 | 공통 문항·평가 정책 검토, 학습 시작·시험·결과·회고의 변경 흐름 작성 | 기초 문항 수동 편입·서술형 길이·초기 평가 개수 표시 확정. 미평가·복습 반영·정정 범위·평가 상태 구분·완료 순번은 남은 검토 |
| 확장 2 | 새 자료 DTO·유형별 검증, 선행 연결 저장 위치, 수동 복습 지정 보존, DB 전환·평가 이력·명령 계약·재계산의 손상 행 정책과 가상 자료 준비 | 기존 JSON 1.0과 과거 시험 유지, 새 형식의 잘못된 유형 거부, 수동 지정을 보존하는 재계산·실패 시 원본 보존 검증 |

| 확장 4 | 소규모 실제 자료 연동·사용자 확인·exe 재생성 | 용어의 난이도와 참고 답안 적절성 확인, 실제 IME·여러 줄 입력·재실행 검증과 문서 갱신 |

확장 2에서는 기본 열 읽기 단계까지 포함한 손상 기록 격리와 후속 시험 완료의 재계산 정책을 설계하고 보완한다. 기본 열 변환 실패도 행별 격리하도록 목록과 화면을 보완했다. 정상 행 뒤에 오류 행을 표시하며 추정 메타데이터와 열기 버튼을 제공하지 않는다. 재계산 중 손상 판정에 대한 전체 차단·해당 문항 오류·표시 후 제외의 선택과 데이터 보존·복습 반영을 계약에 명시하고, 정상 완료뿐 아니라 늦은 평가·정정에서도 같은 정책을 검증한다. 정책이 정해지기 전에 손상 판정을 임의로 건너뛰지 않는다.

기존 줄바꿈 답변의 표시/제출 불일치는 먼저 [원문 복원 방식으로 보완](13_기존답변복원보완.md)했다. 줄바꿈 없는 답변은 한 줄 입력을 유지하고, 기존 여러 줄 답변만 원문을 보존하며 복원한다. [기초 학습과 사용자 평가 화면 초안](../화면흐름/07_기초학습과사용자평가.md)을 작성했으며 확장 1의 정책 선택은 대기 중이다.

기초 학습은 2026-11-26 사용자 방향에 따라 별도 모드·전용 시험 준비 없이 결과·회고에서 연결된 기초 문항을 오답노트에 추가하는 것으로 정리했다. 기존 오답 우선·오답만을 재사용하며 실제 응시 결과와 수동 복습 지정을 구분한다. 서술형 참고 답안은 단답형의 4단어 제한에서 제외하고 초기 평가는 네 구분의 개수만 표시하도록 사용자 확정을 반영했다. 숫자 배점·환산·혼합 합계는 초기 범위에서 제외하며 복습·정정·상태와 순번의 세부 정책은 아직 검토 중이다.

2026-11-26에 [확장 구현 설계 목차](../구현설계/확장/README.md) 아래 자료·저장 구조·명령·DB 전환을 나눠 초안을 작성했다. 기존 `item_progress`의 마지막 응시 필수 제약을 가짜 기록으로 우회하지 않고, 수동 복습 편입의 원천을 실제 응시와 분리했다. 구체적인 권장안·정책 의존성·검사 결과는 [연결 설계 결과](14_확장연결설계.md)에 기록한다. ## 호환과 전환

기존 JSON 1.0은 단답형으로 읽고 기존 질문·답·문항 ID를 자동 재작성하지 않는다. 새 형식은 새 버전으로 검증하며 구형 앱에 서술형 자료를 넣지 않는다. DB 구조 버전과 교환 버전은 별도로 관리한다.

확장 파서의 1.0 경로는 새 유형 전용 필드의 혼입을 거부하도록 구현했다. 기존 앱 등록에는 아직 연결하지 않았다. 알 수 없는 필드의 전면 거부는 기존 자료와 보충 정보의 자유 필드에 영향을 주므로 확정 사항으로 두지 않는다. 확장 파서는 1.0 자유 필드와 보충 payload를 유지하고 2.0 본체/외피는 엄격히 검증한다. 이 경계는 가상 파일로 확인했다.

기존 DB 전환에는 전환 전 보존본·실패 시 복원 절차·트랜잭션 경계를 설계하고 가상 DB에서 검증한다. 평가 이력과 집계의 초기 연결을 확인하기 전 실제 사용자 DB를 전환하지 않는다. 현재 release DB와 개발 DB를 서로 자동 복사하지 않는다.

참고 답안과 핵심 기준은 최종 제출 전 DTO에 포함하지 않는다. 이후 공개되는 기준은 현재 자료가 아니라 출제 당시 기준을 사용한다. 제출한 답변은 정정해 덮어쓰지 않으며, 새로운 평가와 점수·학습 상태 변경을 함께 저장한다.

## 필수 검증

- 단답형만·서술형만·혼합 시험, 단답형 4/5단어와 허용 표기 경계, 알 수 없는 유형·버전의 거부.
- 1.0 파일에 새 유형 필드가 섞인 경우와 보충 정보의 허용된 자유 필드를 구분하는 파서 정책, 기본 열 손상이 있는 목록과 손상 판정이 있는 후속 완료·늦은 평가·정정.
- 최종 제출 전 정답·참고 기준 비공개, 미응답 안내, 제출 원문 보존, 미평가와 시스템 실패 구분, 평가를 나중에 이어서 처리.
- 정답·부분정답·오답·미평가의 확정된 집계 규칙, 예전 평가 정정 후 이후 시도까지 재계산, 자료의 허용 표기와 개별 평가 정정의 분리.
- 평가 요청 중복·오래된 버전 충돌·트랜잭션 중간 실패·화면 이탈/재조회·정상 종료와 재실행.
- 기초 문항 수동 추가·중복 추가·없는 연결 안내, 상위 판정과 점수 불변, 허위 응시 생성 없음, 선택 범위 안의 기존 오답 출제와 재계산 후 수동 지정 보존.
- 기존 시험·완료 순번·프로필 보존, 기존 여러 줄 답변 복원, 한글 조합과 Enter·붙여 넣기·여러 줄 자동 저장.

실제 자료는 로컬 data에서만 보강하고 검증은 먼저 가상 자료와 별도 DB로 수행한다. 문서에는 개수·통과 여부만 남긴다. 기존 답변 복원 보완과 exe 재생성은 별도 결과 문서에 기록했으며, 서술형·평가 기능은 아직 구현하지 않았다. commit·push는 수행하지 않는다.
