# 손상 기록 격리와 평가·오답노트 명령

작성일: 2026-11-26. 상태: 현행 기록 목록 보완과 DB 2용 평가 백엔드 구현·가상 검증 완료. 실제 자료·사용자 DB는 열거나 전환하지 않았고 exe는 재생성하지 않았다. stage·commit·push는 수행하지 않았다.

## 현행 앱의 기록 목록 보완

기본 열을 한꺼번에 변환하던 경로를 행별 읽기로 바꿨다. ID·상태·저장/완료 시각·완료 순번 또는 세부 기록을 읽지 못하면 그 행만 오류로 반환한다. 정상 미완료 → 정상 완료 → 손상 행 순으로 표시한다. 미완료는 저장 시각, 완료는 완료 순번 내림차순이며 손상 행은 DB 행 순서를 유지한다.

DTO는 `kind=exam` 정상 행과 `kind=error` 오류 행으로 나눴다. 오류 행에는 불투명한 `row_key`와 안내만 주고 ID·문항 수·시각을 임의로 채우지 않는다. 화면은 오류 행의 열기 버튼과 날짜·점수를 표시하지 않는다. 상태를 판별할 수 없는 행은 전체 기록에서만 보인다. DB 자체의 읽기 실패까지 행별 복구하는 기능은 아니다.

| 명령 | 구현 결과 |

| `get_assessment_view` | 현재 사용자의 완료 시험만 조회. 원문·유형별 기준·최초/현재 평가·평가/집계 revision·네 개수·현재 복습 상태 반환 |

[평가 서비스](../src-tauri/src/assessment.rs)·[집계](../src-tauri/src/assessment/progress.rs) → DbWorker → Tauri 명령 등록 → [TypeScript bridge](../src/bridge/assessment.ts)까지 연결했다. 네 개수는 조회 트랜잭션에서 계산하고 별도 점수 캐시로 중복 저장하지 않는다.

평가 이력·현재 평가·시험 결과 revision·문항 학습 상태·성공 요청 기록은 한 트랜잭션이다. 동일 요청 재시도는 중복 이력을 만들지 않고 저장된 결과를 반환한다. 같은 요청 ID의 다른 내용/명령과 오래된 평가·집계 버전은 거부한다. 저장 중 실패는 전체 롤백한다. 원천/캐시 불일치를 조용히 복구하거나 손상 판정을 건너뛰지 않는다.

구현은 [권장 정책 초안](<../../공통 개발 문서/상세설계/학습규칙/02_3_평가상태와재계산.md>)을 검증하는 범위다. 부분정답은 대상 유지·연속 0, 미평가는 중립, 미응답은 정정 불가, 수동 편입 뒤 3회 연속 정답으로 해제한다. 이것을 과거 사용자 확정으로 기록하지 않는다. 활성 적용 전에 남은 정책을 검토한다.

## 현재 앱과 분리한 경계

평가 서비스는 기존 파일을 새로 만들지 않고 DB 버전 2만 연다. 현재 DB 1에서는 `UnsupportedDbVersion`으로 거부하며 자동 전환하지 않는다. 현재 일반 Store는 DB 1을 사용한다. 따라서 새로운 명령이 등록됐다는 것만으로 현재 앱에서 서술형 시험·평가 버튼을 사용할 수 있다는 뜻은 아니다.

새 시험 생성·제출·자동 완료의 DB 2 저장소, 선행 기초 문항 조회, 혼합 시험/평가 화면과 활성 전환은 남아 있다. 테스트의 서술형 완료 상태는 가상 DB에 직접 구성해 평가 명령을 검증했다. 실제 앱에서 혼합 시험을 제출한 검증으로 보고하지 않는다.
