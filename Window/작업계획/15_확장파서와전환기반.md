## 사본 전환의 안전 경계

- 원본과 같은 경로 또는 기존 목적지에 덮어쓰지 않는다. Backup API로 WAL의 커밋된 내용까지 일관되게 읽는다.
- 무결성·외래 키·프로필·문항 기준·응답 수/위치·자동 판정·학습 상태의 재계산 일치를 확인한다. 손상 원천을 생략하거나 가짜 이력으로 메우지 않는다.
- V001을 수정하지 않고 사본에만 V002를 적용한다. 완료 응답만 최초 평가로 연결하고 미완료는 미평가로 보존한다. 버전 기록까지 한 트랜잭션으로 처리하고 실패 시 전부 롤백한다.
- 사본을 다시 열어 확인한 뒤 새 파일로 확정한다. 실패한 임시 사본은 정상 오류 반환 시 정리한다. v2 재전환은 거부해 이력을 중복 생성하지 않는다.
- 실제 원본 교체·복원 화면·강제 종료 잔여 파일 처리·디스크 부족은 후속 작업이다. 사본 생성 후 원본에 기록이 추가될 수 있어 활성 전환 때 쓰기 중단과 최종 확인이 필요하다.

Rust는 프로젝트 내부 `.tools/cargo`, `.tools/rustup`을 해당 프로세스 환경에 설정해 실행했다. 새 테스트는 파서 10개·전환 10개로 총 20개이며 기존 43개도 함께 통과했다. 가상 값만 사용했고 실제 문항·답변·사용자 기록은 출력하지 않았다.

파서는 혼합 유형 왕복·새 필드 거부·1.0 자유 필드 호환·경로 이탈·개수 불일치·유니코드/길이 경계·연결 진단과 4,000개 문항의 긴 연결을 검사했다. DB는 진행/제출/완료 공존·줄바꿈 원문·3회 해제·기존 목적지 보존·손상 집계/기본 열·스키마 변경 후 실패 롤백·WAL·재전환 거부·이력 수정 방지를 검사했다.

문서 검사 결과 JSON은 도구가 자동 갱신했다. 이 결과는 앱의 새 평가 흐름이나 활성 DB 자동 전환 검증을 뜻하지 않는다.
