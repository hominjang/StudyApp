# React와 Tauri 전환 수행 결과

작업일: 2026-11-24. 상태: 웹 화면 시제품 확인·네이티브 빌드 환경 준비 중.

아래는 11월 24일 당시의 기록이다. 11월 25일 환경 설치와 네이티브 실행, 자료 연결을 완료한 결과는 [자료 연결 결과](07_자료등록과저장소연결.md)에서 확인한다.

## 변경 내용

Windows 화면을 React·TypeScript·Vite로, 데스크톱 실행과 학습·파일·SQLite 처리를 Tauri 2·Rust로 전환했다. 관련 구현 설계와 초기 구현 결정·진행 계획을 갱신했다. 이전 WPF 검토 문서는 당시의 이력으로 보관하며 현재 기술 기준으로 사용하지 않는다.

`Window/src`에 학습 시작·시험 설정과 기록 화면 시제품을 만들고, `Window/src-tauri`에 기본 실행점과 `get_app_status` 명령을 추가했다. DB·자료 조회·실제 시험·채점 명령은 아직 구현하지 않았다. 자료가 없는 것처럼 실제 DB를 조회하는 대신 화면 미리보기임을 표시하고 시험 시작을 비활성화했다.

학습 규칙·JSON 명세·DB 스키마와 실제 데이터 Git 제외 원칙은 유지한다. 실제 문제·정답을 frontend 코드에 넣지 않았으며 data·복사 resources·node_modules·dist·target·.tools는 Git에서 제외한다.

## 개발 환경과 확인 결과

| 항목 | 결과 |
| --- | --- |
| 웹 실행 환경 | 프로젝트 전용 Node 24.22.3. 공식 ZIP과 SHA-256 대조. 시스템 Node 12.19.1은 변경하지 않음 |
| 웹 의존성 | React 19.3.1·TypeScript 7.0.2·Vite 8.3.8, package-lock.json 생성 |
| 웹 빌드 | TypeScript 검사와 Vite production build 통과 |
| 브라우저 확인 | 직접 지정·전체 전환, 순서 선택, 오답 모드 선택, 기록 이동 후 설정 유지 확인 |
| 입력 가능 상태 | 자료 연결 전 시험 시작 비활성화 확인 |
| 브라우저 로그 | 확인한 개발 화면에서 error·warn 없음 |
| 네이티브 선행 조건 | WebView2 확인. Rust·cargo·MSVC 도구는 미설치 또는 감지되지 않음 |
| 네이티브 빌드 | tauri build --no-bundle 시 cargo metadata 실행 파일을 찾지 못해 실패. Windows 실행·Rust 컴파일은 미검증 |

웹 미리보기는 실제 SQLite나 학습 기록을 사용하지 않는다. 브라우저 검증을 네이티브 앱의 입력·종료·복구 검증으로 계산하지 않는다. Cargo.lock과 검증된 Rust 버전은 Rust 환경 준비 후 추가한다.

## 실행 방법

현재 PC에서는 저장소 루트에서 다음 명령으로 프로젝트 전용 Node를 선택해 실행할 수 있다.

```powershell
& ./Window/scripts/run-web.ps1 -Task dev
& ./Window/scripts/run-web.ps1 -Task build
```

개발 주소는 http://127.0.0.1:1420 이다. 이 프로세스가 실행 중일 때만 미리보기를 열 수 있다. 새 clone에서는 Node 버전과 `npm ci`로 의존성을 먼저 준비한다. `.tools`와 실제 data는 Git에 포함되지 않는다.

## 다음 작업

Rust MSVC 도구 체인·C++ Build Tools를 준비하고 Tauri 실행과 기본 명령 응답을 검증한다. 이어서 Rust application·domain·SQLite 저장 계층을 만들고 로컬 자료 등록과 목록 조회를 연결한다. 1단계의 Windows 실행 기준은 아직 완료되지 않았다.
