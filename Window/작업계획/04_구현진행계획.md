# 학습 앱 구현 진행 계획

작성일: 2026-11-24. 수정일: 2026-11-27. 상태: 1~5단계와 신규 DB 2 혼합 시험·평가/기초 복습 화면 구현/가상 검증 완료. 기존 DB 활성 전환·실제 자료 보강·새 배포는 남음.

기존 여러 줄 답변 복원은 [보완 결과](13_기존답변복원보완.md)와 같이 먼저 처리했다. 확장 1은 [화면 초안](../화면흐름/07_기초학습과사용자평가.md)과 일부 요구 확정까지 진행했다. [확장 2 연결 설계 초안](../구현설계/확장/README.md)을 작성했으며 [파서·사본 전환 기반](15_확장파서와전환기반.md)을 구현·가상 검증했다. [목록 격리와 DB 2 평가/복습 명령](16_손상기록과평가명령.md)도 구현·가상 검증했다. [DB 2 시험 저장소·혼합 UI](17_혼합시험과평가화면.md)도 연결·가상 Windows 검증했다. 다음은 정책 점검과 기존 DB 활성 전환/복원·실제 자료 보강·배포 검증이다.

현재 사용할 수 있는 기능과 미구현 범위의 요약은 [프로젝트 작업 현황](<../../공통 개발 문서/작업계획/04_프로젝트작업현황.md>)에서 확인한다.

구현의 코드 책임과 자료 연결 및 호출 계약은 [구현 설계](../구현설계/README.md)에 작성했다. 작성 결과와 검사 범위는 [구현 설계 검토](05_구현설계검토.md)에서 확인한다.

초기 Android 107문항과 일반 CS 147문항을 사용하는 Windows 학습 앱을 구현한다. 각 단계에서 실행과 검증이 가능한 결과를 만들고 다음 단계로 진행한다. 현재 준비된 자료와 설계 검증 모델은 앱 구현 완료에 포함하지 않는다.

## 구현 순서와 완료 기준

| 순서 | 작업과 산출물 | 완료 기준 | 상태 |
| --- | --- | --- | --- |
| 1. 구현 기반 준비 | Windows 화면 기술·SQLite 연결 방식·빌드와 배포 방식을 선정하고 React 화면과 Tauri 실행 골격 생성. 화면·학습 처리·데이터 관리 책임 분리 | 선택 근거와 실행 방법이 기록되고, 웹 화면 빌드와 Tauri Windows 실행이 확인됨 | 완료 |
| 2. 자료와 저장소 연결 | DB 구조와 사용자 프로필, 초기 자료 등록, 자료 목록 구현 | 두 묶음 254문항이 한 번만 등록되고, 재실행해도 사용자와 자료가 유지됨. 초기 등록 실패는 전체 롤백 | 완료: [결과](07_자료등록과저장소연결.md) |
| 3. 시험 한 회 완성 | 자료·문제 수·표시 순서 선택, 일반 모드 출제, 한 문항 표시와 번호 이동, 제출 확인·채점·결과 화면 구현 | 실제 자료로 시험을 끝까지 풀 수 있음. 제출 전 정답 비공개, 완전 일치 채점, 미응답 안내가 동작하고 판정·완료·학습 상태가 함께 저장됨 | 완료: [결과](08_시험출제와채점.md) |
| 4. 자동 저장과 이어 풀기 | 답변·위치 자동 저장, 편집 버전 관리, 중단 시험 복원, 제출 후 처리 재개 구현 | 저장된 문항·순서·답변·위치로 재개됨. 오래된 요청이 최신 답을 덮어쓰지 않고 완료 재시도로 집계가 늘지 않음 | 완료: [결과](09_자동저장과시험재개.md) |
| 5. 기록과 오답 재학습 | 시험 기록 조회, 과거 판정과 현재 학습 상태 구분, 오답 우선·오답만 출제 연결 | 3회 연속 정답이면 오답 대상에서 제외되고 중간 오답이면 초기화됨. 이전 기록이 선택한 모드의 다음 시험에 반영됨 | 완료: [결과](10_기록조회와오답재학습.md) |

| 7. 통합 검증과 배포 | 실제 화면·한글 입력·오류 경로 검증, Windows 배포 패키지와 설치·실행 안내 작성 | 개발 도구 없이 대상 Windows 환경에서 실행됨. 새 설치와 업데이트에서 자료·기록 보존을 확인하고 초기 버전 필수 기능의 미해결 오류가 없음 | 일부 진행: [exe 실행 폴더](11_Windows실행파일.md). installer·통합 검증은 남음 |

3단계부터 시험을 직접 풀어볼 수 있다. 2026-11-26의 학습 품질 요구에 따라 5단계와 6단계 사이에 [기초 용어·서술형·사용자 평가 확장](12_학습방식확장계획.md)을 추가했다. 기존 완료 단계와 번호는 유지한다. 확장 1~4의 정책 검토→자료/기록 호환 설계→앱 구현→소규모 자료와 사용자 확인 순서로 진행하고, 이후 자료 교환과 7단계 통합 검증을 이어간다.

## 단계별 진행과 검증

각 단계는 필요한 세부 설계 확인 → 구현 → 실행과 검증 → 결과 기록 순으로 진행한다. 기술 선정과 코드 구조 등 세부 결정은 해당 주제의 상세 문서에 작성하고, 폴더 README에서 경로를 안내한다. 이 계획에는 순서와 완료 기준 및 진행 상태를 유지한다.

- 관련 기능을 구현할 때 채점 예시 1,705건과 [설계 검토의 17개 시나리오](02_설계검토.md)를 실제 앱 코드에 맞는 검증으로 연결한다. 독립 모델의 통과 결과로 앱 검증을 대신하지 않는다.
- 각 단계에서 정상 동작과 해당 기능의 실패·재시도를 함께 확인한다. 마지막 단계에서는 실제 화면과 배포 환경에서 전체 흐름을 점검한다.
- 단계가 끝나면 구현 내용·검증 방법과 결과·미해결 항목·실행 방법·다음 작업을 요약한다. 수행 결과는 이 폴더의 별도 구현 기록에 남기고 README에 연결하며, 위 표의 상태를 갱신한다. 필수 완료 기준을 충족하지 못하면 진행 중으로 둔다.

## 시작할 작업

사용자 요청으로 [질문·답 자료 학습](19_질문답자료학습.md)을 추가했다. 기존 DB 1/신규 DB 2에서 현재 자료를 읽으며 시험·평가·오답 상태는 바꾸지 않는다. 기존 단계 번호와 자료 교환/복구의 미완료 범위는 유지한다.

1·2단계는 [자료 연결 결과](07_자료등록과저장소연결.md), 3단계는 [시험 구현 결과](08_시험출제와채점.md), 4단계는 [자동 저장과 재개 결과](09_자동저장과시험재개.md), 5단계는 [기록과 오답 재학습 결과](10_기록조회와오답재학습.md)에 기록했다. [혼합 시험 결과](17_혼합시험과평가화면.md) 뒤에 배포 앱의 [자료 추가·갱신](18_배포앱자료추가.md)을 구현했다. 새 exe는 기존 DB 1에 단답형 가져오기를, 신규 DB 2에 혼합 학습을 지원한다. 다음은 남은 정책 점검·기존 DB 활성 전환/복원·자료 보강과 내보내기/백업이다. 실제 사용자 DB와 자료를 이번 작업에서 전환하지 않았다.

초기 구현은 준비된 두 자료와 기존 학습 요구를 기준으로 하며 별도 로그인 없이 실행한다. 범용 자동 문항 변환기와 추가 원문 변환은 별도 확장 작업이고 기기 간 동기화는 이번 구현 범위에 포함하지 않는다.
