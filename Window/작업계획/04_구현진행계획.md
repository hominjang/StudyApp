# 학습 앱 구현 진행 계획

작성일: 2026-11-24. 상태: 계획 작성 완료·앱 구현 시작 전.

구현의 코드 책임과 자료 연결 및 호출 계약은 [구현 설계](../구현설계/README.md)에 작성했다. 작성 결과와 검사 범위는 [구현 설계 검토](05_구현설계검토.md)에서 확인한다.

초기 Android 107문항과 일반 CS 147문항을 사용하는 Windows 학습 앱을 구현한다. 각 단계에서 실행과 검증이 가능한 결과를 만들고 다음 단계로 진행한다. 현재 준비된 자료와 설계 검증 모델은 앱 구현 완료에 포함하지 않는다.

## 구현 순서와 완료 기준

| 순서 | 작업과 산출물 | 완료 기준 | 상태 |
| --- | --- | --- | --- |
| 1. 구현 기반 준비 | Windows 화면 기술·SQLite 연결 방식·빌드와 배포 방식을 선정하고 프로젝트와 기본 창 생성. 화면·학습 처리·데이터 관리 책임 분리 | 선택 근거와 실행 방법이 기록되고, 빌드 후 기본 창이 실행됨 | 기술·구조 설계 완료, 환경 준비·코드 생성 전 |
| 2. 자료와 저장소 연결 | DB 구조와 사용자 프로필, 초기 자료 등록, 자료 목록 구현 | 두 묶음 254문항이 한 번만 등록되고, 재실행해도 사용자와 자료가 유지됨. 초기 등록 실패는 전체 롤백 | 작업 전 |
| 3. 시험 한 회 완성 | 자료·문제 수·표시 순서 선택, 일반 모드 출제, 한 문항 표시와 번호 이동, 제출 확인·채점·결과 화면 구현 | 실제 자료로 시험을 끝까지 풀 수 있음. 제출 전 정답 비공개, 완전 일치 채점, 미응답 안내가 동작하고 판정·완료·학습 상태가 함께 저장됨 | 작업 전 |
| 4. 자동 저장과 이어 풀기 | 답변·위치 자동 저장, 편집 버전 관리, 중단 시험 복원, 제출 후 처리 재개 구현 | 저장된 문항·순서·답변·위치로 재개됨. 오래된 요청이 최신 답을 덮어쓰지 않고 완료 재시도로 집계가 늘지 않음 | 작업 전 |
| 5. 기록과 오답 재학습 | 시험 기록 조회, 과거 판정과 현재 학습 상태 구분, 오답 우선·오답만 출제 연결 | 3회 연속 정답이면 오답 대상에서 제외되고 중간 오답이면 초기화됨. 이전 기록이 선택한 모드의 다음 시험에 반영됨 | 작업 전 |
| 6. 자료 교환과 복구 | JSON 가져오기·내보내기, 갱신 미리보기, 백업·복구와 DB 구조 버전 처리 구현 | 자료 갱신 후에도 기존 시험을 보존함. 교환 실패 시 부분 적용이 없고 백업 복구 후 기록과 식별자가 유지됨 | 작업 전 |
| 7. 통합 검증과 배포 | 실제 화면·한글 입력·오류 경로 검증, Windows 배포 패키지와 설치·실행 안내 작성 | 개발 도구 없이 대상 Windows 환경에서 실행됨. 새 설치와 업데이트에서 자료·기록 보존을 확인하고 초기 버전 필수 기능의 미해결 오류가 없음 | 작업 전 |

3단계부터 시험을 직접 풀어볼 수 있다. 자동 저장·재개와 기록 반영 및 자료 교환을 순서대로 붙이고, 7단계에서 초기 버전 전체를 확인한다.

## 단계별 진행과 검증

각 단계는 필요한 세부 설계 확인 → 구현 → 실행과 검증 → 결과 기록 순으로 진행한다. 기술 선정과 코드 구조 등 세부 결정은 해당 주제의 상세 문서에 작성하고, 폴더 README에서 경로를 안내한다. 이 계획에는 순서와 완료 기준 및 진행 상태를 유지한다.

- 관련 기능을 구현할 때 채점 예시 1,705건과 [설계 검토의 17개 시나리오](02_설계검토.md)를 실제 앱 코드에 맞는 검증으로 연결한다. 독립 모델의 통과 결과로 앱 검증을 대신하지 않는다.
- 각 단계에서 정상 동작과 해당 기능의 실패·재시도를 함께 확인한다. 마지막 단계에서는 실제 화면과 배포 환경에서 전체 흐름을 점검한다.
- 단계가 끝나면 구현 내용·검증 방법과 결과·미해결 항목·실행 방법·다음 작업을 요약한다. 수행 결과는 이 폴더의 별도 구현 기록에 남기고 README에 연결하며, 위 표의 상태를 갱신한다. 필수 완료 기준을 충족하지 못하면 진행 중으로 둔다.

## 시작할 작업

1단계의 기술은 [기술 선정](../구현설계/00_기술선정.md)에 정리했다. 다음은 .NET 10 SDK 준비, 패키지 정확한 버전 고정과 프로젝트 생성 후 기본 창의 빌드·실행 검증이다.

초기 구현은 준비된 두 자료와 기존 학습 요구를 기준으로 하며 별도 로그인 없이 실행한다. 범용 자동 문항 변환기와 추가 원문 변환은 별도 확장 작업이고 기기 간 동기화는 이번 구현 범위에 포함하지 않는다.
