# 일반 모드 시험과 채점 구현 결과

작업일: 2026-11-25. 상태: 구현 진행 계획 3단계 완료.

아래는 3단계 완료 당시의 기록이다. 이후 자동 저장·이어 풀기·제출 처리 재개는 [4단계 결과](09_자동저장과시험재개.md)에서 확인한다.

## 사용할 수 있는 기능

선택한 자료와 문제 수·전체 출제·무작위 또는 순서대로 설정으로 일반 모드 시험을 생성한다. 한 문항씩 풀면서 이전·다음 버튼이나 번호 목록으로 이동하고, 메모리에 입력한 답변을 유지한다. 최종 제출 확인에서 미응답 수와 문항 번호를 안내하고 답변으로 돌아가거나 그대로 제출할 수 있다.

제출 전 화면에는 질문과 입력 답변만 전달한다. 대표 정답과 허용 표기는 시험 생성 시 DB 스냅샷에 보관하고 전체 제출·채점 완료 후 결과에서 공개한다. 정답과 등록 허용 표기를 완전 일치로 비교하며 trim·대소문자 변경·Unicode 정규화를 하지 않는다. 미응답은 React와 Rust 모두 공통 명세의 고정 White_Space 25자로 판정한다.

결과에는 정답 비율·정답·오답·미응답 수, 문항별 답변·정답·허용 표기·현재 오답 상태를 표시한다. 전체·오답·미응답 필터와 공백 문자 표시를 제공한다. 연결 가능한 현재 해설을 펼칠 수 있고, 같은 설정을 유지한 자료 선택 화면으로 돌아갈 수 있다.

## 저장과 재시도

시험 생성은 설정과 문항 순서·질문·정답 스냅샷을 함께 저장한다. 시작 요청을 재시도할 때 같은 시험 ID와 설정이면 기존 시험을 반환한다. 다른 설정으로 같은 ID를 사용하면 거부하며 재추출하지 않는다.

최종 제출은 전체 답변 원문·위치·revision과 submitted 상태를 한 트랜잭션으로 저장한다. 완료 처리는 판정·완료 순번·completed 상태·문항 학습 상태를 별도 트랜잭션으로 확정한다. 중간 오류는 해당 작업 전체를 롤백한다. 이미 제출된 답변은 수정하지 않으며, 완료 재시도나 결과 조회로 학습 집계를 중복 반영하지 않는다.

오답 대상의 3회 연속 정답 집계는 완료 처리의 일관성을 위해 구현했다. 오답 우선·오답만 출제와 과거 시험 목록 화면은 5단계에서 연결한다. 제출·채점 오류 시 화면은 입력을 잠근 채 같은 요청을 재시도하며, DB 상태가 in_progress임을 확인한 경우에만 답변 수정으로 돌아간다.

## 실행과 검증

저장소 루트에서 실행한다. 도구와 로컬 자료 준비, Rust 테스트 환경 변수는 [자료 연결 결과](07_자료등록과저장소연결.md#실행-방법)를 따른다.

```powershell
& ./Window/scripts/run-web.ps1 -Task tauri:dev
& ./Window/scripts/run-web.ps1 -Task test
& ./Window/scripts/run-web.ps1 -Task build
```

| 검증 | 결과 |
| --- | --- |
| TypeScript 검사·Vite 빌드 | 통과 |
| Rust 기본 테스트 | 27개 통과, 실제 자료용 3개는 별도 실행 |
| 실제 자료용 테스트 3개 | 초기 등록·재실행, 254문항 시험 제출·완료·재조회, 채점 예시 1,705건 모두 통과 |
| React 공백 판정 테스트 | 전체 Unicode 범위의 고정 25자·제외 문자·공백 표시 3개 통과 |
| Windows 화면 | 가상 3문항으로 시험 생성·번호 이동·입력 유지·제출 취소·미응답 안내·최종 제출·결과 확인 통과 |
| 화면의 정확 채점 | 허용 표기 정답·공백 수 차이 오답·U+0085 미응답을 확인. 정답 1·오답 2·미응답 1 |
| 결과 화면 | 공백 수·U+0085 표시와 미응답 필터 확인 |
| Windows 재실행 | 완료 시험 1개·응답 3개·오답 대상 2개 유지, 원문 공백 보존·DB 무결성 확인 |

Rust 테스트는 중복 생성·완료 재시도, 소유자와 위치 검사, 잘못된 개수·revision 거부, 제출 전 결과 차단, 원본 변경 후 스냅샷 채점, 생성·제출·완료 중간 오류의 전체 롤백, 알 수 없는 채점 규칙 거부를 포함한다. 실제 자료 테스트는 임시 DB에서 수행했고, Windows 화면 테스트는 .tools의 가상 자료·별도 DB를 사용했다. 기존 실제 자료와 사용자 DB에 검증용 시험을 추가하지 않았다.

## 다음 작업과 제한

다음 4단계는 자동 저장·중단 후 이어 풀기·제출 처리 재개다. 현재 작성 중 답변은 메모리에 유지하고 최종 제출 시 저장한다. 제출 전에 앱을 닫으면 입력을 잃을 수 있음을 화면에 안내한다. 창 종료 전 저장과 재실행 후 진행·처리 중 시험을 여는 화면은 아직 없다.

완료 결과는 DB에 보관하지만 과거 시험 목록을 통한 조회는 5단계에서 구현한다. 배포 설치 패키지는 7단계다. 실제 문항·정답·답변은 이 문서나 검증 로그에 넣지 않는다.
