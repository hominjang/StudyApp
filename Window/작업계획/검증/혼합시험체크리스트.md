# 혼합 시험·사용자 평가 확인

작성일: 2026-11-27. 대상: 이번 소스로 빌드한 DB 2 앱. 기존 배포 exe는 아직 새 기능을 포함하지 않는다. 체크는 사용자가 확인한 뒤 표시한다. 자동/가상 Windows 검증은 [작업 결과](../17_혼합시험과평가화면.md)에 별도로 기록했다.

## 별도 검증 환경

현재 작업 환경에는 직접 만든 가상 자료 `.tools/mixed-ui-qa/initial`이 있다. 실제 사용자 DB와 분리된 새 `.tools/user-mixed-review` 저장소로 실행한다. 이 자료와 도구는 Git 제외 로컬 산출물이므로 새 clone에는 없을 수 있다. 없는 환경에서는 가상 2.0 자료를 먼저 준비한다.

저장소 루트 PowerShell에서 실행한다. frontend를 내장하는 debug 실행이므로 개발 웹 서버는 필요하지 않다. 환경 변수는 이 PowerShell 프로세스에만 적용한다.

```powershell
& ./Window/scripts/run-web.ps1 -Task build
$env:CARGO_HOME = Join-Path (Get-Location) '.tools/cargo'
$env:RUSTUP_HOME = Join-Path (Get-Location) '.tools/rustup'
$env:STUDYAPP_INITIAL_DIR = Join-Path (Get-Location) '.tools/mixed-ui-qa/initial'
$env:STUDYAPP_DB_DIR = Join-Path (Get-Location) '.tools/user-mixed-review'
$env:TAURI_CONFIG = '{"identifier":"com.hominjang.studyapp.review","build":{"devUrl":null,"beforeDevCommand":null},"app":{"windows":[{"label":"main","title":"StudyApp 검토","width":1240,"height":860}]}}'
& "$env:CARGO_HOME/bin/cargo.exe" +1.100.0 run --manifest-path Window/src-tauri/Cargo.toml --features tauri/custom-protocol --offline
```

기존 DB 1 폴더를 지정하면 기존 단답형 흐름을 유지한다. 위 별도 경로의 신규 DB 2와 구분하며 파일을 직접 바꿔 끼우지 않는다.

## 확인 항목

- [ ] 가상 자료 전체·순서대로 시험을 시작한다. 단답형은 한 줄, 서술형은 처음부터 여러 줄 입력이다. 제출 전 정답·참고 답안·핵심 내용이 보이지 않는다.
- [ ] 서술형에서 한글 조합 중 Enter와 문항 이동을 확인한다. 여러 줄 붙여 넣기·자동 저장·저장 후 나가기·재실행 후 답변과 위치를 확인한다.
- [ ] 미응답이 있으면 제출 안내에 번호가 나오고, 제출하면 오답으로 남는다. 응답한 서술형은 미평가로 표시된다.
- [ ] 결과는 정답·부분정답·오답·미평가 개수이며 합계가 문항 수와 같다. 참고 답안·핵심 내용과 제출한 여러 줄 답변이 보인다.
- [ ] 평가하지 않고 기록으로 나갔다가 평가 대기 필터의 같은 시험을 다시 연다. 답변과 기준이 그대로이고 시험 수가 늘지 않는다.
- [ ] 서술형을 부분정답으로 저장하고 나중에 정답으로 정정한다. 최초 평가와 현재 평가가 구분되고 제출 답변은 바뀌지 않는다.
- [ ] 연결된 기초 문항을 조회하고 오답노트에 추가한다. 상위 문항의 판정·시험 문항 수는 그대로이며 현재 오답 학습 준비에 기초 문항이 포함된다.
- [ ] 같은 기초 문항은 중복 추가되지 않는다. 복습 중 3회 연속 정답이면 해제되고 중간 오답/부분정답은 연속 횟수를 초기화한다.
- [ ] 평가/편입 저장 중에는 다른 변경과 이동을 막는다. 오류가 나면 같은 요청 재시도 또는 최신 상태 확인으로 복구하며 저장되지 않은 평가를 성공으로 표시하지 않는다.
- [ ] 종료·재실행 후 평가/정정과 수동 복습 대상이 유지된다. 결과 보기만 반복해도 새 시험·정답 횟수가 추가되지 않는다.

## 기록할 내용

통과 여부·환경·재현 순서와 오류 코드만 적는다. 실제 문항·정답·입력 답변·사용자 기록은 체크리스트나 보고서에 옮기지 않는다. 실제 사용자 DB 활성 교체/복원과 새 배포 exe 검증은 별도 후속 작업이다.
