# 초기 자료 등록과 SQLite 연결 결과

작업일: 2026-11-25. 상태: 구현 진행 계획 1·2단계 완료.

이 문서는 1·2단계 완료 당시의 기록이다. 이어서 완료한 3단계의 시험·채점 기능은 [시험 구현 결과](08_시험출제와채점.md)에서 확인한다.

## 사용할 수 있는 기능

Windows 앱의 첫 상태 조회에서 로컬 초기 자료를 검사하고 SQLite에 등록한다. 자료 2묶음·254문항과 로컬 프로필 하나를 함께 저장하며, 재실행 시 기존 DB를 사용한다. 자료 선택·해제, 여러 자료 선택, 선택 순서 변경과 조건별 문항 수 표시를 연결했다. 목록 응답에는 질문·정답을 포함하지 않는다.

새 DB는 같은 폴더의 임시 파일에서 구조 생성·등록을 한 트랜잭션으로 처리하고 무결성 확인 후 최종 이름으로 확정한다. 기존 DB의 손상·지원하지 않는 버전·등록 표시와 데이터의 불일치는 초기 자료로 덮어쓰지 않는다. 자료 준비 후 오류 화면의 재시도로 초기화를 다시 실행할 수 있다.

## 실행 방법

현재 PC에 Microsoft C++ Build Tools 2022와 Windows SDK 10.0.26100.0을 설치했다. Rust 1.100.0과 Node 24.22.3은 저장소의 Git 제외된 .tools에 준비했고 시스템 Node와 영구 PATH는 바꾸지 않았다. 의존성은 package-lock.json·Cargo.lock과 rust-toolchain.toml로 고정한다.

저장소 루트에서 실행한다.

```powershell
& ./Window/scripts/run-web.ps1 -Task tauri:dev
```

이 명령은 로컬 data/initial의 catalog와 지정된 학습·보충 JSON 5개를 Git 제외된 resources/initial-data에 복사하고 웹 서버와 Windows 앱을 함께 실행한다. 개발 DB는 .tools/runtime/study.db를 사용한다. debug 빌드에서는 STUDYAPP_DB_DIR·STUDYAPP_INITIAL_DIR로 검증 경로를 바꿀 수 있다. 일반 앱 경로는 LOCALAPPDATA/StudyApp/study.db다.

새 clone에는 .tools·실제 data·의존성 폴더가 없다. 해당 도구와 자료를 별도로 준비해야 한다. 자료가 없으면 최초 등록 오류를 표시하며, 이미 등록된 DB는 초기 JSON 없이도 다시 열 수 있다. 브라우저 미리보기는 DB를 사용하지 않는다. 설치 패키지와 배포용 resources 매핑은 7단계에서 구현한다.

이 PC의 Rust 테스트는 저장소 루트에서 다음과 같이 실행한다. 환경 변수는 현재 PowerShell 프로세스에만 적용된다.

```powershell
$env:CARGO_HOME = Join-Path (Get-Location) '.tools/cargo'
$env:RUSTUP_HOME = Join-Path (Get-Location) '.tools/rustup'
& "$env:CARGO_HOME/bin/cargo.exe" +1.100.0 test --manifest-path Window/src-tauri/Cargo.toml --locked
$env:STUDYAPP_TEST_INITIAL_DIR = Join-Path (Get-Location) 'data/initial'
& "$env:CARGO_HOME/bin/cargo.exe" +1.100.0 test --manifest-path Window/src-tauri/Cargo.toml --locked private_local_data_roundtrip -- --ignored
```

## 검증 결과

| 검증 | 결과 |
| --- | --- |
| TypeScript 검사·Vite production build | 통과 |
| Rust 기본 테스트 | 14개 통과, 실제 자료 테스트 1개는 기본 실행에서 제외 |
| 실제 로컬 자료 테스트 별도 실행 | 2묶음·254문항 등록과 재실행 통과 |
| Windows 앱 첫 실행 | 자료 2묶음·254문항 표시 확인 |
| Windows 앱 조작 | 한 자료·두 자료 선택, 선택 순서 변경, 오답 대상 없음 안내 확인 |
| Windows 앱 종료 후 재실행 | 2묶음·254문항·프로필 1개 유지, 이전 프로필 동일 확인 |
| 실제 개발 DB 무결성 | integrity_check = ok |
| 데이터 Git 제외 | 원본 53개·앱 자산 사본 5개 제외 확인, 실제 자료 index 추적 0개 |
| 원본 자료 보존 | 작업 전후 53개 파일의 경로·내용 SHA-256 집계 동일 |
| 개발 서버 자료 접근 | 초기 자료 catalog의 HTTP HEAD 요청이 403으로 차단됨 |
| 문서 링크·diff 공백 검사 | 오류 없음 |

Rust 검증에는 고정 공백 25자와 제외 문자, ID 길이·ASCII 경계, 잘못된 자료 거부, 보충 source_refs 보존, 실패 시 전체 롤백, 기존 손상·지원하지 않는 버전 보존, 자료 수정 후 재시도와 초기 JSON 없는 재실행을 포함한다. 실제 문항·정답·답변은 이 기록과 로그에 싣지 않는다.

## 남은 작업

시험 시작은 비활성화되어 있다. 다음 3단계에서 일반 모드 시험 생성·문항 표시와 이동·제출·채점·결과 조회를 구현한다. 자동 저장·이어 풀기·오답 기록 반영·자료 교환·복구·배포 설치 파일도 이후 단계다. 현재 화면의 출제 조건과 순서 선택은 시험 생성에 전달할 화면 상태까지 구현했다.
