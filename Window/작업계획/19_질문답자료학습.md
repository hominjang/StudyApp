# 질문·답 자료 학습 구현

작성일: 2026-11-27. 상태: DB 1/2 읽기 전용 조회·자료 학습 화면·가상 자동 검사·Windows 창 검증·새 release 실행 폴더 생성 완료. 실제 자료 원본·사용자 DB는 수정하지 않고 stage·commit·push는 하지 않았다.

## 구현 결과

| 영역 | 결과 |
| --- | --- |
| 화면 | **자료 학습** 메뉴·전체/자료 하나 선택·질문 검색·질문과 답 동시 표시·20개 페이지 이동 |
| 단답형 | 대표 정답·허용 표기와 선택 해설을 원문 공백/줄바꿈을 유지하며 표시 |
| 서술형 | 참고 답안·핵심 내용과 선택 해설 표시. 점수·제출·판정 입력 없음 |
| 기록 보존 | 조회만 수행. 시험 생성·응답·완료 순번·평가 이력·오답 대상/연속 정답을 바꾸지 않음 |
| 호환 | DB 1 단답형과 DB 2 혼합 자료를 현재 저장소에서 읽음. DB 전환·스키마 변경 없음 |
| 예외 | 조회 중 조건 변경/화면 이탈의 오래된 응답 무시. 자료 없음·검색 결과 없음·오류/재시도 구분 |

`StudyWorkspace` → `bridge/study.ts` → `browse_study_materials` → `DbWorker` → `RuntimeStore` → `study_material.rs` 순서다. UI에는 읽기용 `StudyPage`/`StudyItem`을 반환한다. 시험 작성 DTO는 계속 정답을 포함하지 않는다. 이 조회는 과거 시험 스냅샷이나 사용자 답변이 아니라 현재 활성 자료를 공개한다.

입력은 선택 자료 ID 또는 null(전체), 질문 검색 문자열(최대 512 UTF-8 바이트), 정렬된 페이지 offset·limit(1~50)이다. 현재 화면은 검색 입력 128자·페이지 20개를 사용한다. 하나의 읽기 트랜잭션에서 개수와 항목을 조회하며 자료/문항 순서 뒤 ID로 안정 정렬한다. 비활성 문항은 제외하고 범위를 넘긴 페이지는 마지막 페이지로 맞춘다. 질문 검색은 바인딩한 문자열의 부분 일치이며 SQLite 기본 lower 기준으로 영문 대소문자를 구분하지 않는다. 답안·응시 답변은 검색하지 않는다.

DB 2 기준은 유형 태그·채점 기준을 검증한 뒤 반환하고 DB 1은 같은 읽기 DTO로 변환한다. 손상된 기준을 빈 정답으로 대신 보여주지 않고 조회 오류로 안내한다. 문자열은 HTML로 실행하지 않고 텍스트로 표시한다. 별도 읽음 기록이나 위치 저장은 이번 범위에 포함하지 않는다.

Rust 신규 7개는 두 DB 버전 정답/해설 조회·기존 진행/완료 시험과 진도 무변경·같은 문항 ID의 자료별 구분·범위/페이지·검색 문자 그대로 처리·비활성/빈 결과·경계 거부·서술형 원문/손상 거부·작업 큐 연결을 검사했다. 조회 전후 SQLite `total_changes`가 같고 기존 시험 DTO·오답 대상이 유지됨을 확인했다. 화면 신규 2개는 질문·정답/허용 표기·참고 답안/핵심 내용의 동시 표시, 제출/입력 동작 없음, HTML 이스케이프를 실제 컴포넌트 정적 렌더로 확인했다. 모두 직접 만든 가상 자료만 사용했다.

## Windows 창과 실행 파일

`com.hominjang.studyapp.readqa` 식별자와 `.tools/read-ui-qa`의 가상 자료/DB로 debug 앱을 실행했다. 실제 사용자 저장소를 열어 확인한 것은 아니다.

- 가상 2묶음·22문항에서 **자료 학습** 진입과 단답 질문·대표 정답·허용 표기 동시 표시 확인.
- 1–20번에서 다음 페이지 21–22번으로 이동하고 서술형 참고 답안·핵심 내용이 포함됨을 확인.
- 가상 질문 검색으로 결과 1개와 여러 줄 참고 답안·핵심 내용 표시 확인.
- 키보드로 단답 묶음을 선택했을 때 같은 검색 조건의 결과 없음 안내, 검색 지우기 후 해당 묶음 21개·첫 페이지 복귀 확인.
- 검색은 편집 API로 입력했으므로 실제 한글 입력기 조합 검증으로 보고하지 않는다. 다음 페이지는 조작했고 이전 페이지 경계는 자동 검사와 코드로 확인했다.
- 정상 종료 후 가상 DB를 읽기 전용으로 확인했다. 묶음 2개·문항 22개·프로필 1개를 유지했고 시험·응답·학습 상태·평가/학습 이벤트·변경 요청은 모두 0개였다. 무결성 통과·외래 키 오류 0개이며 검증 창은 닫았다.

새 실행 위치는 `Window/artifacts/StudyApp-0.1.0-windows-x64-20261127T013516524Z/StudyApp.exe`다. 초기 자료와 실행 안내를 포함한 폴더 전체를 사용하며 이전 실행 폴더와 실제 사용자 DB는 유지했다. 배포 exe 자체를 사용자 DB로 열어 화면 조작한 것은 아니다.
