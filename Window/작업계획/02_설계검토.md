# 초기 설계 연결 검토 결과

검토일: 2026-11-24. 설계 문서와 독립 모델의 검토 결과이며 실제 앱 구현 완료를 뜻하지 않는다.

## 1. 저장 방식 설계

JSON은 자료 교환, SQLite는 실행 중 자료와 학습 기록 보관에 사용한다. 최초 설치, 자료 갱신, 답변 저장, 제출, 완료, 백업과 구조 변경의 처리 경계를 주제별로 작성했다.

답변과 입력 위치는 편집 버전으로 저장하고, 완료 판정과 시험 상태 및 학습 상태는 함께 확정한다. 실패 시 전체 되돌림과 같은 시험 재시도를 기준으로 삼았다. 상세 내용은 [저장 방식 목차](../저장방식/README.md)에서 찾는다.

## 2. 남은 검토안 정리

자료 미선택·10문항·무작위·일반을 새 시험 기본값으로 정했다. 빈 답과 공백뿐인 답은 미응답으로 처리하며 입력 원문은 유지한다. 초기 버전은 완료 결과 수정과 시험 기록 삭제를 제공하지 않고 새 시험으로 재학습한다.

오답 우선의 선택과 표시 순서를 구분하고, 가져오기 미리보기와 내보내기 흐름을 연결했다. 필드와 세부 동작의 상태 표기도 초기 설계 기준으로 통일했다. 사용자 요구와 이번에 선택한 구현 기준은 [초기 설계 결정](<../../공통 개발 문서/작업계획/03_초기설계결정.md>)에서 구분한다.

## 3. 전체 연결 검토

자료 준비 → 범위 선택 → 출제와 초기 저장 → 답변과 자동 저장 → 중단 후 재개 → 제출 → 채점과 완료 저장 → 결과 확인 → 오답 재출제를 검토했다.

| 발견한 모호함 또는 실패 위험 | 반영한 기준 |
| --- | --- |
| 과거 자동 저장 요청이 최신 답을 덮어쓸 수 있음 | 증가하는 `revision`, 낮은 버전 무시, 같은 버전의 다른 내용은 충돌 |
| 시간 변경이나 동시 완료로 연속 정답 순서가 흔들림 | 사용자별 유일한 `completion_order`를 완료 트랜잭션에서 부여 |
| 일부 판정만 저장되거나 완료 재시도가 횟수를 늘림 | 판정·완료·학습 상태 전체 확정과 완료 기록 기준 재계산 |
| 자료 수정·제거로 진행 중 질문과 채점 기준이 변함 | 질문·정답·허용 표기·자료명을 시험에 보존 |
| 오답 우선에서 표시 순서를 해석하기 어려움 | 선택 우선순위와 전체 표시 순서를 따로 정의 |
| 배포하지 않은 원문 파일 때문에 학습 자료 사용이 막힘 | 작성 과정의 원문 연결 검증과 앱의 출제 자료 검증을 구분 |
| 가져오기·내보내기 접근 경로가 불분명 | 자료 선택에서 진입하는 별도 화면 흐름 문서 추가 |

### 실행한 검증

- 독립 SQLite 설계 모델의 **17개 시나리오 통과**. 초기 자료 설치 실패, 오래된 저장 요청, 제출 후 입력, 완료 직전 장애와 재시도, 3회 연속 정답과 초기화, 시계 역행, 원문 제거, 자료 갱신 실패, 관계 제약, 임시 백업 복원을 포함한다.
- 초기 자료 두 묶음 **254문항**의 식별자를 사용하고, 포함된 채점 예시 **1,705건**을 완전 일치 규칙으로 다시 확인했다.
- 문서의 로컬 경로 참조는 별도 스크립트로 검사한다. 검사 수와 오류 목록은 [경로 검사 결과](<../../공통 개발 문서/작업계획/검증/문서경로검사결과.json>)에 기록한다.

시나리오별 결과와 재실행 경로는 [검증 목차](검증/README.md)에서 확인한다. 모델은 실제 앱 저장 코드가 아니며, 실제 UI·IME 입력·저장 타이머·파일 잠금·다중 프로세스·디스크 장애·전원 종료·DB 마이그레이션은 검증하지 않았다.

## 구현으로 이어갈 작업

UI 프레임워크와 SQLite 연결 방식을 정하고, 두 초기 자료를 사용해 시험 생성부터 저장·재개·결과·오답 재출제까지 구현한다. 이후 실제 앱에서 화면 경로와 저장 실패 시나리오를 검증한다. 범용 자동 문항 변환기와 추가 원문 변환은 별도 확장 작업으로 남긴다.
