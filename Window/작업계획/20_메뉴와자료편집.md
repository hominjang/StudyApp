## Windows 창 검증과 실행 파일

별도 식별자 `com.hominjang.studyapp.editqa`와 `.tools/edit-ui-qa`의 가상 2묶음·22문항 DB로 debug 앱만 조작했다.

- 메뉴 네 개의 순서·시험 시작 이름과 상단 경로 표시 확인.
- 첫 단답 문항 편집에서 5단어 정답 저장 거부·입력 유지 확인.
- 유효한 정답과 여러 줄 해설을 저장한 뒤 최신 카드에 표시됨 확인.
- 다시 편집해 임시 변경 후 취소했을 때 저장한 내용 유지 확인.
- 편집 중 창 닫기는 안내 후 보류되고 편집을 유지함 확인. 취소 후 정상 종료 확인.
- 자료 추가의 파일 선택·내용 확인·양식 버튼에 같은 테두리·모서리·크기 스타일이 적용됨을 화면에서 확인.

종료 후 가상 DB를 읽기 전용으로 점검했다. 자료 revision 2·문항 22개·묶음 2개, 저장한 정답 유지와 해설 줄바꿈 보존을 확인했다. 시험·응답·학습 상태·평가/학습 이벤트는 모두 0개이며 무결성 통과·외래 키 오류 0개다. 기존 기록이 있는 경우의 보존은 위 Rust 테스트에서 확인했다.

입력은 접근성 편집 API로 수행했다. 실제 IME 조합·화면에서의 서술형 편집·저장 실패 재시도·서로 다른 화면의 동시 충돌은 직접 조작하지 않았으며 해당 기준/거래 경로는 자동 검사로 구분한다.

새 실행 위치: `Window/artifacts/StudyApp-0.1.0-windows-x64-20261127T054233353Z/StudyApp.exe`. 초기 자료와 실행 안내를 포함한 폴더 전체를 보관한다. 이전 실행 폴더는 유지했고 새 exe와 자료도 Git에서 제외했다. 새 release 자체를 실제 사용자 DB로 열어 화면 검증한 것은 아니다.
